`filter_parameters` semantics (phoenix 1.8.15 `discard_values/3`): substring match on binary keys, recursion into maps/lists; the new list covers every sensitive field of the 9 forms; `endpoint`, `iam_endpoint`, `sts_endpoint`, `bucket`, `region`, `s3_key_prefix_template`, scopes, refresh modes are configuration, not secrets, deliberately not masked. Deny-list keeps old keys and does not blank other controllers.

Checks without finding: gate not weakened (every POST still `gate(conn, :marker, path)`, `reauth_remaining_minutes/2` calls `reauth_fresh/2` first and writes nothing, TOCTOU ends in the server-side refusal, `consume_reauth` after the write at all sites, role-mapping refactor changes only the second refusal tuple element, fingerprint check untouched); no open redirect / href injection (href from server constant or `seg/1` client id, `return_to` re-validated by allowlist regex, `mode=reauth` start needs an admin session); no XSS (HEEx escaping, no `raw/1`); no value in URL/flash/session; OIDC scopes law untouched; CSRF/click proof fields stay, link is a plain GET `<a>`; cross-site trigger of `/admin/login/start?mode=reauth` = forced re-auth, acceptable (victim must sign in at the IdP with `max_age=0`, result only a marker in own session, spending it needs a same-origin CSRF-tokened click POST); no session/header size growth (read-only assign); docs match code except #1 and #4.

Pattern for memory: two logging paths: `filter_parameters` covers only `Phoenix.Logger`; `Nebu.Web.Plugs.RequestLogger` debug body capture runs over `/admin` form bodies with PayloadRedactor exact keys. Any "not in logs at debug" claim must check both.
