# media-storage-admin-target — follow-ups

Items found by the reviews of story `media-storage-uses-admin-config` that are deliberately NOT part of it. None blocks the
story; each is a small change of its own (some need a decision about the pinned wording).

| # | Item | Why deferred |
|---|---|---|
| 1 | **Early validation errors still use the top-of-page flash.** Required endpoint / bucket, a scheme prefix, an invalid IAM / STS endpoint (`media_settings_controller.ex`, `validate_storage_params/1` and `do_save_storage/2`) show the message at the top without `aria-invalid` / focus, unlike the errors of the storage validation (code review cycle 3, MINOR-3). | Needs the same `storage_save_error` rendering for the field-level errors; no security impact. |
| 2 | **Copy accuracy of the pinned key hints** (cycle 3, MINOR-4): "Required now: enter both the access key and the secret key." is shown after ANY refused save, also an invalid endpoint; "Required: Save and Test Connection both need both keys." overstates (a legacy row with an endpoint and no keys can still be saved for an unrelated field); the orphan alert sentence "Enter the access key and secret key again before saving." is shown for bucket-only changes too. | The strings are pinned by tests; changing them is a contract change. |
| 3 | **A key rotation is refused when the stored endpoint does not resolve** (cycle 3, MINOR-5): a save with keys always writes `endpoint` and `use_ssl`, so `upsert/2` runs the SSRF / DNS check on the stored endpoint; if it no longer resolves, or a stored private endpoint is no longer allowed, the admin sees "Endpoint rejected" for a field they did not touch and has no way to rotate the keys from the page. Needs a hint text (and possibly a way to rotate without the endpoint check). | Documented trade-off in `07-deployment.md`; the break-glass SQL clears the row. |
| 4 | **Test Connection accepts one typed key** (cycle 3, INFO-5): a typed key plus the stored other key of the same target is used for the test; Save refuses a lone key. No hole (the stored key goes only to the stored target). | Asymmetry only; align when the form copy is revisited (item 2). |
| 5 | **`persisted_target/0` and `persisted_iam_sts/0` read an unreadable row as fresh / nil** (the orphan-risk gate and the IAM / STS baselines are skipped while the row cannot be read). The write itself needs the database as well, so the effect is small. | Making them return an error touches the controller's IAM / STS baseline logic. |
| 6 | **IAM / STS endpoints are not bound by `same_target?`**: the Test Connection and the credential rule compare endpoint and Use SSL only. Nothing calls the IAM / STS endpoints today; they must join the comparison if anything ever does. | No caller. |
| 7 | **DNS rebinding residual (`ds`)**: the operational S3 calls are not SSRF-pinned; the check runs at save time only, and rows saved before the M-3 validation were never checked. Live since this story (`docs/stories/oauth-broker/follow-ups.md` row `ds`, `11-risks.md`). | Options in row `ds` (pinned client with periodic re-check, or an egress policy). |
| 8 | **Concurrent save race**: two administrators saving at the same moment can overwrite each other; the key rule reads the row and the write follows, not as one atomic step (a save of the endpoint alone checks, then writes). Severity LOW, accepted (single-admin console in practice), documented in `07-deployment.md`. | A conditional write (compare-and-set on `set_at`) would close it. |
