## Findings
| # | Sev | Location | Finding | Remediation |

| L-1 | LOW | server.ex `validate_room_alias_name/1` | Alias namespace spoofing / squatting (`eo`). The localpart rule rejects only `\s`, C0, DEL, `:`, NUL; it accepts invisible/bidi format characters (U+200B, U+200E, U+202E RLO, U+2066, U+FEFF), C1 controls, Cyrillic homoglyphs, case variants and `/ ? # %`. `room_aliases.alias` PK is case-sensitive TEXT (`#General` and `#general` coexist). Any user can register any free localpart; createRoom has no rate limit / per-user cap. Impact limited today: no `/directory/room`, `POST /join/#alias` never resolves an alias (`em`). | Reject Unicode Cf and Cc now (Nebu policy); case-insensitive uniqueness, reserved localparts, per-user cap, createRoom rate limit = owner decision `eo`. Becomes MEDIUM the day `em` lands. |
| L-2 | LOW | protected.ex createRoom, server.ex | Depth cap (D5a) does not cover `creation_content` (m.room.create content): ~160k levels fit in the 1 MB cap, unbounded through Jason/CanonicalJson, jsonb stack-depth; the m.room.create write is non-fatal so the room can exist without a create event.
