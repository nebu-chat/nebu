I-8 kill switch: off => register/authorize/token/JWKS/openid-configuration/account 404, m.oauth 403; still live: revoke, /logout, /logout/all, OAuth access tokens until expiry (<= 3600 s); sessions survive and re-enabling revives them; runbook revoke SQL deletes only matrix_sessions (wording corrected). I-9 unauthenticated endpoint inventory: rate-limited per IP: register, authorize, callback, token, refresh, JWKS, revoke, account; not limited: auth_metadata, auth_issuer, aliases, openid-configuration, /versions, GET /login; every per-IP bucket is global behind nginx until gate 1.

Cross-story patterns: (1) consent rests entirely on the DCR approval (D5): its integrity (E-3, story-1 F-5), the ability to undo it (E-1) and interactive IdP login (E-2) are all open gates; (2) hardening created an undo gap ("a decision is final" removed approved -> withdrawn); (3) prerequisites left to the IdP (freshness, interactive login) should be server-enforced fail-closed checks; (4) one origin for three trust levels (Element Web, /account, /admin).

Accepted risks carried over (13): legacy m.login.sso bypasses DCR approval while both APIs run; `/logout/all` without UIA (Matrix spec); GDPR erasure does not deactivate; other nodes accept a raw JWT <= 60 s after a failed denylist write; reuse detection bounded by session lifetime (RFC 9700); authz request consumed before the binding check; in-flight codes (<= 60 s) survive `/logout/all`; no IdP-side refresh-token revocation (t); raw IdP JWT path until legacy deprecation (u); 3-day metadata cache vs kill switch; FORCE RLS/triggers do not stop a compromised owner role; legacy cross-signing replacement 403 instead of UIA (pre-existing); switch-off suspends instead of revoking (ai).

Verdict: CLEAN for the dormant merge; activation blocked: gates 1, 2, 4, h, i, l, m, n, r, y, ac (+af), ag (incl. /admin), aj and ak(1) must close first.
