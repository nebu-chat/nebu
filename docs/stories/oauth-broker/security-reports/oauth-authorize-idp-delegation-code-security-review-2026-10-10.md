Baseline: story-1 report and follow-ups.md (trusted-proxy IP hard gate not raised again).

Verified clean: PKCE S256 only (43 char anchored), exact redirect URI match with a safe loopback port exception, Location built only from registered values with encode_www_form, no redirect before client/redirect_uri are trusted, IdP error text never forwarded, per-flow binding cookie compared in constant time, atomic single-use DELETE...RETURNING, `iss` on every response (RFC 9207), `o2.` tag checked before legacy logic and impossible in legacy states, IdP tokens verified through the shared path with nonce check, IdP refresh token SecretBox-encrypted, provisioning identical to legacy POST /login with deactivation check, 256-bit codes stored as SHA-256 only, TTL CHECK 60 s, single-use UPDATE with guard trigger, RLS forced with no UPDATE grant on authz requests, parameterized SQL, strict raw-query parsing, pages with CSP (style hash) / no-store / no-referrer / CORS removed, request logger logs only parameter names on both paths (normalized path), No-Sensitive-Data-in-Logs law respected, JsonBody bypass limited to /oauth2/authorize, kill switch answers 404 before any rate-limit token or DB access, test seams not set in lib/config.

INFO: I-1 trusted-proxy gate (follow-up (a)) covers the new buckets; wording "before story 2 merges" in the gate text should be reconciled before a merge to main (merging to the feature branch with oauth_enabled off is acceptable). I-2 request consumed before binding check (accepted, ADR-033). I-3 story-3 obligations: re-check `is_active`, verify redirect_uri and PKCE against the row, revoke on code reuse, issue id_token when `openid` requested, handle device reuse (D9) deliberately. I-4 nginx access logs still contain the IdP `code` on the callback query: operator note to strip query strings for these paths. I-5 loopback match is case-sensitive at authorize vs case-insensitive at registration (fails closed). I-6 one path-scoped cookie per unfinished flow (negligible).

Verdict: APPROVED (CLEAN).
