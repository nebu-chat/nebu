## Detail

**Visibility.** Ordinary branch reads `e.room_id = $1` inside `[GREATEST(s.lo, floor), s.hi]` of visible segments and excludes rows matching `@sql_hv_special_event`; segments are disjoint closed ranges covering the time axis, so this equals the plain read's `hv_a.vis[width_bucket(ts, los)]`. Special branch is a PK lookup on `hv_special` with `sp.vis`, `LIMIT 1`, `y.room_id = $1` afterwards; the set equals the fragment's special predicate; branches are disjoint (no duplicates). `room_id = $1` in floor, ordinary and special branch; `hv_in` holds one room. Bounds `COALESCE(room_pos,0) > $3 AND <= $4` in both branches; legacy NULL never matches; events committed after the head read excluded. hv joined/invited/shared/world_readable, hidden stretches and own member events give the same verdict as the plain read. Floor and lookback can only remove candidates. Base-0 path uses `fetch_visible_events/6`.

**Delivery, gate, cost.** `limited`/`prev_batch`/order keep the `visible_range!` contract; an event at or below the base is never returned (strict `>`). `latest_member_events` returns `room_pos`, so `member_positions` is real data. Member events are stamped `max(now, not_before, latest_member_ts + 1)`: the newest member event by timestamp is also newest by position; any leave/kick/ban of the viewer after the base writes a member event above the base, so the room is gated. Row-only leave + re-join (no member events) means the fragment sees the viewer joined throughout, no hidden stretch, plain read stays cheap. Clients cannot set `origin_server_ts`, so a member cannot widen another user's scan or lower another user's floor beyond commit latency. Replay uses the previous generation's base; current member events are still above it, so the gated bounded read repeats. Cost per request: fragment O(B log B) (gk), segment probes O(B), rows read at most sum over segments of min(21, new visible rows) plus about 64 + skew rows at or below the base plus rows committed after the head, specials O(own member events) (gk residual); none depends on hidden ordinary history. Many rooms / many re-joins scale linearly in requests that are rate limited (600/min). `messages_db_module` is not set in any config; `viewer_read/3` never falls back for the real `Room.DB`.

**Residuals.** Timestamps are server-stamped and per-room writes serialise positions through the trigger's `rooms` row lock, so residuals (1) and (2) need real cross-writer skew or commit latency and cannot be steered by an attacker; effect is omission only, the event stays reachable via `/messages`; `state.events` is the full current state minus the timeline, so a skewed state event is not lost (at worst one sync late if the timeline comes back empty). D-A2 is a real regression only for the worst plan in a `shared` re-join: O(M) against the old 21; the planner cannot be steered by a user, the four plan regimes are pinned at no more than 100 rows, never O(hidden).

**Failure path and LOG LAW.** A segmented-read error goes to `history_read_failed!/3` (`server.ex` ~3417): existing value-free line, raised 503 `M_UNAVAILABLE`, nothing persisted (dispatcher test :446-475), no new log line. D-A7 verified: logged by `RequestLogger` `Logger.debug` at `request_logger.ex:228-239`. Production: unreachable by default (`config/prod.exs:3` `level: :info`, no log-level env override in `config/runtime.exs`; the admin `log_collect_debug` toggle only controls persistence). Reachable with MIX_ENV=dev (`config/dev.exs:3` `:debug`) or an operator running `Logger.configure(level: :debug)` from a remote console, then entries also reach the operational log store and the War Room. `since` is a 16-byte random nonce naming nothing, only usable with the device's bearer token, not a credential. The ATDD statement "sync response body (chat content)" is overstated: `PayloadRedactor` masks `content`/`prev_content` children (except metadata keys) and `body`/`formatted_body`/`name`/`topic`/`displayname`/`reason`/`filename` at any depth; residual is client-chosen strings outside `content` (finding 2). `QueryTelemetry` logs no params. The new HTTP "logs" test filters the request-logger lines out, so it proves nothing about them. Severity LOW, pre-existing, not introduced by this diff.

**SQL injection.** All values bound (`$1..$5`); interpolations are compile-time constants (`@sql_history_visibility`, `@hv_event_columns`, `@sql_hv_special_event`, integer `@rejoin_floor_lookback - 1`); guards require integers. Clean.

**Privileged DDL test.** `DROP INDEX events_room_id_ts_idx` and EXPLAIN run inside `Postgrex.transaction` and end with `Postgrex.rollback`; DDL is transactional, a crash aborts the transaction. Side effects: ACCESS EXCLUSIVE lock on `events` during the EXPLAIN; `ANALYZE events` commits (harmless); `unstamp!` commits `room_pos = NULL` on fixture ids only. Matters only if the suite is pointed at a production database with migrate credentials (finding 6).

**Docs vs reality.** 06-runtime, the `cq` (f) closure and the `/sync` row match the code (gate = max of latest and previous, base 0 like an absent base, no timeout, residuals (1)-(3) named). Inaccuracies: "floor rises" on gaps (finding 1) and "a hidden row is never read" (finding 5); "continuously joined room: the stretch is empty" holds apart from skew-bounded late commits.

## Summary

CRITICAL 0, HIGH 0, MEDIUM 0, LOW 2 (#1 new, cost-only and unreachable in production today; #2 pre-existing D-A7), INFO 5. **Verdict: APPROVED. MEDIUM-1b CLOSED.** D-A7 (finding 2) is for the owner to decide.
