## Verdict on G3-3 (independent re-check)

No path mints a `loginToken` for an unlisted https target without the confirmation page (old nodes during a rolling deploy excepted, X-5).

- **Mint sites.** `SsoLogin.mint_login_token/2` is the only token writer, with exactly two callers: `redirect_with_login_token/4` (reached only from `finish_legacy_login/5` for `:direct` targets or when `listed?/2` is true) and `SsoConfirm.apply_decision(_, _, "continue")`. Other callback branches mint nothing: `o2.` states branch off before any `SsoStore` access, UIA states render a page, a stored URL that no longer classifies gets a 403; the callback re-classifies the stored RAW string and `Location` is built from that same string (`append_login_token/2` only touches the query and the fragment).
- **Parser** (`sso_redirect.ex`). Rejected: userinfo `@`, `%` in the authority, backslash anywhere, every byte in `\x00-\x20` and `\x7F`, non-ASCII, IPv6 literals, trailing dot / empty label, `_`, an empty or invalid port or one above 65535, non-canonical numeric hosts (hex, octal, single integer), `https:evil` / `https:/evil`. Scheme and host lower-cased, `:443` / `0443` collapse to the default port, query / fragment split at the first `/ ? #` like WHATWG. `http` only for the exact hosts `localhost` / `127.0.0.1`; `javascript data file vbscript blob` are denied before the operator schemes, `https` / `http` are matched before the operator list. No checked-vs-used differential found.
- **`listed?/2`.** `server_name` comes from config, never from `Host`; the operator list is re-normalized per token; source 3 (`trusted_redirect_url?/2`) uses one parse for origin and URL, a registered-URI path boundary, an escaped `LIKE` with `ORDER BY`, a 500 ms bound and fails closed (residual: X-4).
- **Confirm store.** 256-bit `__Host-` cookie (HttpOnly, SameSite=Lax), only its SHA-256 is stored; CSRF token derived from the cookie and domain-separated from the consent page; `pop_confirm` before minting, the GET only peeks; Origin plus lenient fetch metadata; binding per browser (no cross-session fixation); `Referrer-Policy: same-origin` page plus `no-referrer` 303 (no Referer leak of the token); every `SsoStore` call catches exits (no `id_token` in a crash log).
- **Routing.** The JsonBody / CORS skips match on `path_info` (trailing slashes and `//` variants covered); RequestLogger normalizes the path before its names-only check.
- **Migration 000048.** The up migration is the 000042 list verbatim plus exactly `sso_extra_redirect_schemes` and `sso_redirect_allowed_origins` (diffed); the down migration is byte-identical to 000042; no `WITH CHECK` change; no other key loosened.

## Memory candidates (Kassandra)

1. When a story adds an admin config key that silently grants trust (an allowlist, a scheme, a mapping), its write path needs at least the hardening of the comparable approval (strict fetch metadata, fresh re-auth, `frame-ancestors 'none'`); under a shared origin a plain same-origin `fetch` reads the Phoenix CSRF token, so session + CSRF alone is not enough.
2. Path-boundary prefix trust must also refuse `;` (`..;`) and `%25`, not only `.`, `..` and `%2e` / `%2f` / `%5c`.
3. A per-IP bucket on a page that is live without the feature flag inherits the client-IP collapse (G3-2) from the merge on, not from activation.
