## OPS-1 (operational, rated HIGH for deployments)
`Http.sync_response/3` always emits `"invite" => %{}`; Element discovers invitations only through `/sync rooms.invite`. After deploy every invite-only room (new Element private rooms, private Spaces, all legacy rooms without a rule) is invisible and unjoinable in the Element UI for non-members (only `/join !roomid:server` after an invite); Element DMs are broken end to end (createRoom invite not processed: eb; and not shown). Previously "share the room id / link" worked because of the open join. Strong recommendation: do not release to Element-based deployments without the rooms.invite sync section and eb (or ship them together). Release notes must state: (1) security fix, bans enforced, private rooms no longer open to anyone who knows the id; (2) rooms without a join rule are invite-only: run Q1, restore `public` where intended; (3) invitations are NOT shown in Element yet and DMs do not work until eb + the invite sync section; invited users use `/join <room id>`; (4) Admin "Visibility: Public" is a label only (et), Admin force-add of a banned user fails, no Admin unban; (5) the new createRoom 400s; (6) run Q2 for incident review.
