# Story 16.3: Architecture Documentation - arc42 + ADRs

Status: ready-for-dev

## Story

As a developer or architect evaluating Nebu,
I want all arc42 sections (01–12) and ADRs (ADR-001 to ADR-015) browseable on the website,
So that I can understand Nebu's architecture and key decisions without digging through the Git repo.

**Size:** M

## Acceptance Criteria

**Given** the `pages` CI job in `.gitlab-ci.yml`,
**When** it is inspected,
**Then** it copies `docs/architecture/` to `website/dokument/architecture/` before running the EasyWebsite build - no committed copy under `website/`, `docs/architecture/` remains the single source of truth (NFR-16.2)

**Given** `website/dokument/_meta.yaml`,
**When** the site renders,
**Then** an "Architecture" section appears in the sidebar with:
- sub-entries for arc42 sections 01–12
- a dedicated "Architecture Decision Records" sub-section listing all 15 ADRs

**Given** a visitor navigates to `/architecture/`,
**When** the page renders,
**Then** all 12 arc42 sections are linked and render without 404 errors

**Given** a visitor navigates to `/architecture/adr/`,
**When** the page renders,
**Then** all 15 ADRs (ADR-001 to ADR-015) are listed and each opens without 404 errors

**Given** `docs/architecture/adr/ADR-001-elixir-otp.md` is updated in the repo,
**When** the CI pipeline runs on `main`,
**Then** the updated content appears on the website - no manual copy required

## Technical Notes

- NFR-16.2: No content duplication - `docs/architecture/` is the single source of truth
- The CI pipeline copies `docs/architecture/` to `website/dokument/architecture/` at build time
- This means `website/dokument/architecture/` must be in `.gitignore` (or just not committed)
- Navigation in `_meta.yaml` must reference the architecture section
- ADR files must follow the naming convention that EasyWebsite can discover

## Acceptance Tests

### Tests written FIRST (before implementation code):

1. [CI copy step test] - Manual CI inspection
   - Given: `.gitlab-ci.yml` `pages` job
   - When: job script is inspected
   - Then: there is a `cp -r docs/architecture/ website/dokument/architecture/` step (or equivalent)

2. [Navigation structure test] - Manual site inspection
   - Given: the website is built and served
   - When: sidebar navigation is inspected
   - Then: "Architecture" section exists with sub-entries for arc42 sections and ADR sub-section

3. [No 404 test] - Manual site inspection
   - Given: the website is built
   - When: each linked arc42 section and ADR page is visited
   - Then: all pages return HTTP 200

4. [Single source of truth test] - Manual verification
   - Given: `website/dokument/architecture/` is not committed to git
   - When: `git ls-files website/dokument/architecture/` is run
   - Then: no files are tracked (directory is generated by CI only)
