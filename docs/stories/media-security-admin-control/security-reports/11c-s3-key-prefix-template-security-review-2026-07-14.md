# Security Review — 11c-s3-key-prefix-template

**Reviewer:** Kassandra (nebu-agent-kassandra) · **Date:** 2026-07-14 · **Epic:** media-security-admin-control
**Story flag:** `security_review: optional` — coordinator opted to run it anyway. Correct call: this is a template-interpolation / path-validation function with direct S3-key / path-traversal implications, exactly the shape of feature where "optional" is the wrong default.

## Verdict: CLEAN — APPROVED with accepted risk (0 CRITICAL, 0 HIGH, 0 MEDIUM, 2 LOW, 3 INFO)

Nothing blocks the commit. `validate_template/1`'s path-escape logic is airtight **against the template itself** — I traced every rejection branch and every accepted hierarchical shape and could not construct a template string that escapes the namespace while passing validation. The single write path (`upsert/1`) genuinely gates every persisted template, the atom-key-only design closes the string-key bypass, `compute_key/2` is a pure, stateless, zero-call-site function so the "write-once" invariant cannot be violated on this branch, and the two runtime-substituted values are verified server-derived and safe-by-construction **today**. The two LOW findings are latent defense-in-depth gaps that become live only through the wiring instruction this story hands to the not-yet-landed Story 2b — they are recorded as forward-carry watch-flags for 2b's review, not blockers here.

## What I verified and could NOT break (positive confirmations)

- **Template path-escape is airtight.** Traced `check_no_path_escape/1`'s per-segment split (`Regex.split(~r/\{[^{}]*\}/)`): leading-`/` checked on the first segment only, `..`/`//` on every segment. Confirmed it rejects `"/{media_id}"`, `"../{media_id}"`, `"{media_id}/../x"`, `"a//{media_id}"`, `"{media_id}.."` and accepts `"{year}/{month}/{day}/{server_name}/{media_id}"` and the User-Story example — the MAJOR-1 fix is genuinely correct, not a false pass. Boundary-spanning `..` (e.g. `".{media_id}."`) does not reconstitute a traversal because the unique `media_id` sits between the dots.
- **Brace + placeholder logic sound.** `check_balanced_braces/1` (depth-1 counter) rejects nesting (`"{{media_id}}"`), reversed (`"}{"`), and dangling (`"{media_id"`, `"{media_id}{"`); `Regex.scan`/`split` share one regex so token-check and escape-check see a consistent set; empty `"{}"` is caught by the placeholder allowlist. `{media_id}` mandatory-presence enforced.
- **Single write path + no bypass.** `upsert/1 → default_writer/2 (INSERT…ON CONFLICT)` is the only lib write to `media_storage_config`; `validate_template_field/1` runs *before* `build_columns/1`/the writer (no partial write, no audit row on rejection). `column_for/2` is atom-key-only, so a string-keyed `"s3_key_prefix_template"` is silently dropped — it can neither persist nor bypass validation. `validate_template/1` also fail-closes on non-binary input.
- **Runtime-value trust claims hold today.** `media_id` = `strong_rand_bytes(16)` base64url (globally unique, no path chars, not client-influenced); `server_name` = server app-config. AC6 collision-resistance is true by construction via mandatory `{media_id}`.
- **DoS surface is negligible.** `validate_template/1` is O(n) and runs once, admin-authenticated, at save time; `compute_key/2` is O(n) with no call site. No unbounded runtime amplification.

## Pattern notes for the sanctum

- **"Safe by accident of the encoding" (F-1)** is the same shape as the alg-confusion "defense-by-accident" entry: the path-escape guarantee holds only because `Base.url_encode64` happens to exclude `/` and `.` — change the id scheme or the `server_name` source and the guarantee silently evaporates, with validation looking at the wrong string. When a validator inspects an input but the security property depends on a *different, later-substituted* string, that gap is the finding.
- **Validate-the-template ≠ validate-the-output** — recurring for any interpolation/templating feature. The reviewer must follow the tainted value to the sink, not stop at the validated form.
