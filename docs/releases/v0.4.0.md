# Nebu v0.4.0

Released 2026-11-11. Nebu is **pre-alpha and not production-ready**; see
[Current Limitations](../../README.md#current-limitations) before evaluating.

This is the largest release so far. Since v0.3.0 (2026-05-27) the server was rebuilt as **one
Elixir/OTP application**, and it gained Spaces, advanced room management, a media security pipeline,
Nebu as an OAuth 2.0 authorization server and client-side E2EE support. The complete list is in
[CHANGELOG.md](../../CHANGELOG.md); the diff is
[v0.3.0...v0.4.0](https://gitlab.opencode.de/nebu/nebu-server/-/compare/v0.3.0...v0.4.0).

## Highlights

- **Single Elixir/OTP stack.** The Go gateway, the Go media gateway and the gRPC layer are gone
  (ADR-019, ADR-021). One `nebu-server` image, SQL migrations run at boot.
- **Nebu as OAuth 2.0 authorization server** (ADR-033): `auth_metadata`, dynamic client registration,
  admin approval of clients, remembered consent, an admin-configurable session lifetime, and an
  "Apps" page where users withdraw consent. **Shipped switched off** (`server_config` `oauth_enabled`,
  default `false`); an admin enables it at runtime in the admin UI.
- **Client-side E2EE support**: server-side key backup, to-device messaging, device-key directory,
  restricted key queries and cross-user signatures. Rooms stay unencrypted (ADR-011); a compliance
  guard refuses `m.room.encrypted` events on every room write path.
- **Matrix Spaces, advanced room management, moderation routes, power levels, redaction** and
  history-visibility enforcement on every read path.
- **Media security and admin control** (ADR-024 to ADR-032): asynchronous virus scanning (ClamAV, Oban),
  media state machine, admin media table, retention / archive / orphan workers, kill switch.
- **Hardened container**: non-root, distroless `zendis/base`, digest-pinned, no `curl`.
- **Deployments**: UpCloud example with PostgreSQL TLS (custom CA); StackIT and UpCloud object storage.
- **Operations**: "War Room" page and trace map without extra infrastructure.
- **Fixed on the way**: freshly uploaded images show in Element again (downloads wait for the virus scan instead of answering `451`); the UpCloud example works with a private-only object storage; Element Web `v1.12.33`; the runtime role gets access to five tables that had no grant (migration `000064`).

## Upgrade notes (from 0.3.0)

Read these before you upgrade. Items marked **BREAKING** need action.

1. **BREAKING: new deployment shape.** Drop the Go gateway and media-gateway containers and run the
   single `nebu-server` image. Migrations (up to `000064`) run automatically at boot.
2. **BREAKING: `NEBU_MINIO_*` is now `NEBU_MEDIA_STORAGE_*`.** The old names are ignored *silently*: the
   server boots with the defaults and media fails. Rename every variable before you upgrade (full table
   in the CHANGELOG). Local compose secrets `.secrets/minio_*` are renamed to `.secrets/media_storage_*`
   (`make setup` does it). The local object store is RustFS instead of MinIO, and the old `minio_data`
   volume is not migrated.
3. **BREAKING: OIDC is bootstrap-only** (ADR-022). Issuer, client and audience come only from the
   Bootstrap Wizard; the `NEBU_OIDC_*` / `NEBU_ADMIN_OIDC_*` variables that carried them are removed
   (only `NEBU_OIDC_JWKS_TTL` is still read). The base scope is `openid`; an admin adds more scopes in
   the admin UI.
4. **Non-root image.** The server runs as uid/gid 53111 on a hardened base without `curl`. Mounted secret
   files must be readable by that user; health checks use `/app/healthcheck`. An existing VM's
   `docker-compose.yml` must be patched in the same step as the image upgrade.
   **An existing VM keeps its old secret files** (cloud-init writes them only on the first boot): with mode `0600`/`0700`
   the server stops at boot with `File.Error ... "/run/secrets/internal_secret": permission denied`. Fix it on the VM:
   `chmod 0644 /opt/nebu/.secrets/{internal_secret,s3_access_key,s3_secret_key} && cd /opt/nebu && docker compose up -d`
   (the directory `/opt/nebu/.secrets` stays `0700`). A new VM from the current templates gets `0644` itself: run
   `tofu` from an up-to-date checkout of `main`, an older checkout still writes `0600`.
5. **Storage endpoint behaviour.** An empty `NEBU_MEDIA_STORAGE_ENDPOINT` aborts the boot (UpCloud and
   StackIT templates can render it empty). A saved endpoint is only used with the credentials saved with
   it; saving a changed endpoint or Use SSL needs both keys again.
6. **Stricter Matrix answers** (marked ⚠ in the CHANGELOG): `keys/query`, `keys/signatures/upload`,
   `/event`, `/relations`, redaction and state writes, power levels, moderation routes, history
   visibility values.
7. **Migration order and rollback.** `000058` to `000061` (E2EE) must reach a database after `000056` and
   `000057`; a normal upgrade runs them in order. Rolling back `000058` / `000059` discards every user's
   key backup and all queued to-device messages. `000051` takes an ACCESS EXCLUSIVE lock on `events`
   (maintenance window on large installations; see `docs/architecture/07-deployment.md`).
   `000063` builds an index on `events` and blocks writes until it is done (reads continue); on a large installation
   run it in a maintenance window or build the index beforehand (statement in the migration header).
   `000064` grants the runtime role `nebu_app` access to five tables that had no grant: with separate roles
   (managed PostgreSQL) the server is only fully functional with it, it needs no action.
8. **Local development with Dex.** The dev Dex issuer is now `http://dex.localtest.me:5556/dex`; an already
   bootstrapped dev database needs its stored `oidc_issuer` updated (command in the CHANGELOG) or a reset
   (`make dev-reset-db`).

## Security

- `ecto` 3.14.2 to 3.14.3: EEF-CVE-2026-118391 (CVSS 8.9, unbounded query-cache growth).
- `decimal` 3.1.1 to 3.1.2: CVE-2026-97853. All `mix hex.audit` advisories are cleared.
- The `zlib` findings of the former Alpine runtime image (ALPINE-CVE-2026-4738) no longer apply: the
  runtime image no longer contains `apk`, `curl` or `zlib`.
- History visibility is enforced on every event read path (see the CHANGELOG, "Security").

## Known limitations

- Pre-alpha; not production-ready.
- Rooms are not end-to-end encrypted on the server side (Compliance Mode, ADR-011); there is no
  federation by design.
- Rate limits are node-local (N times in a cluster).
