# Kassandra design review of follow-up `de` (2026-10-15, read-only, before implementation)
Pre-existing state of the unswept forms: HIGH (storage target M2: a same-origin script plus one lured click can send every future upload to an attacker's store), MEDIUM (media policy M1: irreversible deletion settings; test connection M3), LOW (several). Nothing blocks the dormant merge; all of it must be fixed before a release exposed to untrusted same-origin scripts.
Classification (a) marker / (b) strict only / (c) unchanged: M2 (a); M1 (a) (one form-level gate, one marker for the page /admin/media/settings, accepted: the page holds ONE object); M3 (b) + logic fix; L1 (b) + audit, NO marker (raising levels is an operator action while the IdP is broken); U2 (b) (the incident-response kill switch, must work with the IdP down); R6/S6 (b) (a marker would need per-room bindings and a sign-in for routine onboarding); R3 (b); R2/S3 (b) + R2 audit; R4/R5/R7 (b); U1, R1, S1, S2, S4/S5 (b) (S2/S4/S5 are unaudited: a blind script must not change them both ungated and unaudited); bootstrap (c) (owner constraint); logout (c); LiveView (c) with the residual stated honestly.
Facts that changed the picture: M3 does not send the secret itself (SigV4) but the access key id and a signature that allows offline guessing, to a host the credentials were never meant for; the pinned SSRF target of the storage test / save path is discarded (DNS-rebinding window, pre-existing); `released_delete_after_days` / `deleted_days` / `infected_days` of 0 wipe all released media and the infected evidence irreversibly; the `de` row names user role / deactivation actions that do not exist; `scan_kill_switch` cannot be set from any admin endpoint; L1 only touches INFO / DEBUG rows; `configure_logging` is dormant.
Logic fix required for M3 (small, safe): reuse the stored credentials only when the submitted endpoint and scheme equal the stored ones (IAM / STS not compared), else `:secret_required`.
Audit: R2 (call the existing audited function) and L1 (`save_config_audited/3` + a new known action) are part of this hardening; owner / compliance decisions (follow-ups, not closed): S2/S4/S5, `configure_logging`, War Room / diagnosis, bootstrap completion and logout, the media policy audit that is written after the write; row `ab` stays open.
Recommended order: M3 fix + :click; M1 + M2 :marker on /admin/media/settings (regex literal, notice, nav_for, break-glass SQL documented); :click on every remaining post / DELETE with a route enumeration test and strict headers in the unit tests; R2 / L1 audit; docs and follow-ups.
