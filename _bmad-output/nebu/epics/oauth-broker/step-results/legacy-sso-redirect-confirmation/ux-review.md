# UX gate: legacy-sso-redirect-confirmation (nebu-ux-reviewer, static review, 2026-10-13)

2 BLOCKING, 12 NON-BLOCKING. The pages are otherwise a good copy of the consent baseline (one main, one h1, dl, 44 px targets, visible focus, 320 px reflow, escaping, no animation, forced-colors CSS).
BLOCKING
- B1 Continue can stay disabled forever for screen-reader touch-exploration users and nothing explains it: render Continue `aria-disabled="true"` (not `disabled`), `aria-describedby` to the hint (give it an id), add a polite live region that announces "Continue is now available.", add a `focusin` arming signal (focus moved to a non-Continue element), reword the hint to cover all paths, hint visible by default and hidden on arming (resilient if the script fails).
- B2 A real click on an armed Continue is silently swallowed when no `pointerenter` happened after arming: give feedback in the live region ("Move the pointer off and back onto Continue, then click."), rule unchanged.
NON-BLOCKING: N1 plain wording (why the page appears, what Cancel does, 5-minute expiry, xn-- explanation); N2 monospace boxed origin; N3 aria-describedby of Continue includes notice and origin; N4 no role=status on the static notice; N5 distinct `<title>` per page (static strings); N6 noscript text; N7 shared CSS module (later); N8 admin form: label for/id + `aria-describedby` for the help text; N9 restructure the help text (short sentence, bold trust warning, list of auto-allowed origins, cross-reference to the schemes form); N10 keep the typed value and show the error under the field (`aria-invalid`, `role=alert`); N11 textarea (optional); N12 form accessible name (optional).
