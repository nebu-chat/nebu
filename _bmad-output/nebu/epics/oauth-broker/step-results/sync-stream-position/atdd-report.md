## 8. Story gaps / ambiguities with proposed amendments

1. **D8 re-base rule is literally sticky.** "a row whose `gen = generation` is re-based" would rewrite EVERY row that ever changed on EVERY later sync (the rewritten row has `gen = generation` again), contradicting D3 ("an incremental sync WRITES only the rows whose values changed"). Needed only for a request whose base is the PREVIOUS token (a retry). Pinned: D3 (xmin test, base = current). Amend D8: "...OR (the request's base is the previous generation AND gen = generation)".
2. **D9 vs the old AC10 test.** An inviter ignored then un-ignored: the room is no partition room while ignored (cursor deleted), so the invitation ENTERS the partition and is delivered once (no base row = new).
