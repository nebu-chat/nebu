# Oracle gate story 6 oauth-account-management (2026-10-10) (v1.18 + js-sdk 41.3.0 + Element Web 1.12.22 source)
## Spec
account_management_uri optional URI, account_management_actions_supported string[] (https not required by spec; Nebu rule stricter). Server MAY accept `action` and `device_id`; if device_view/device_delete advertised, SHOULD support device_id; actions not supporting device_id ignore it. Actions: profile, devices_list, device_view, device_delete, account_deactivate, cross_signing_reset (server SHOULD use it in the m.oauth url). OAuth-aware clients MUST link to the URL for account management/deactivation and deep-link sign-out of other devices with action=org.matrix.device_delete&device_id=. m.oauth valid ONLY on /keys/device_signing/upload: 401 with `m.oauth` in flows and params["m.oauth"]={url} (url REQUIRED, http/https, https recommended); client opens it, then sends auth:{session}. device_signing/upload UIA required unless (a) no master key stored or (b) the request's master key matches stored AND every additional key supplied also matches. A request without auth always gets 401; completed stages cannot be retried.
## Client behaviour
Element first calls makeRequest(null) (needs error.data.flows), then InteractiveAuthDialog makes a SECOND auth-less request without passing the session => A14 pending-session reuse is load-bearing. Element opens params[stage].url exactly as given (window.open), appends nothing, retry sends {type:"m.oauth", session} (even for unstable stage); no polling, user clicks Retry. 401 with errcode/error => error state: keep the challenge without errcode. Element device links use `org.matrix.device_view` + device_id (fallbacks org.matrix.session_view, bare session_view; with no actions list: org.matrix.session_view); URLSearchParams uses `+` for spaces. "Manage account" opens bare URI without action => default page. Element hides native deactivation, disables multi-select sign-out, shows Manage links whenever metadata has account_management_uri, also for LEGACY sessions.
