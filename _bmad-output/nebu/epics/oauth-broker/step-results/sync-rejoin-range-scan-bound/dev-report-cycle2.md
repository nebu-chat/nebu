1. **Fallback rewritten (Kassandra D1, review A).** `db.ex` `rj_floor`: `CASE WHEN $3 <= 0 THEN NULL ELSE COALESCE(window min, fallback range min) END`; the fallback is `min(origin_server_ts)` over `room_id = $1 AND room_pos BETWEEN $3 + 1 AND LEAST($3 + 64, $4)` behind its own `OFFSET 0` (no ORDER BY / LIMIT left). Corrected in `dev-report-cycle1.md` and `mutation-dev-cycle1.txt`: the old "FB07 ORDER BY removed is equivalent" claim was wrong (without ORDER BY the LIMIT may take any 64 rows, e.g. in heap order under a bitmap scan, floor too high, visible events lost).
