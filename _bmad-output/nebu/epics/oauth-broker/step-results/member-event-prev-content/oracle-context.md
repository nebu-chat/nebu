# Oracle gate (Matrix v1.18) — member-event-prev-content
Spec facts: UnsignedData (§Room Event Format) defines exactly 5 keys: age, membership (v1.11, SHOULD where practical), prev_content, redacted_because, transaction_id. `prev_sender` and `replaces_state` are Synapse EXTENSIONS (0 hits in the bundle). prev_content: "generated by the local homeserver, only returned if the event is a state event, and the client has permission to see the previous content"; lives in `unsigned` (since v1.2). Endpoints whose UnsignedData includes it: /sync, /events, /events/{id}, /initialSync, /rooms/{id}/event/{id}, /members, /state, /messages, /rooms/{id}/initialSync, /relations (3), /notifications, /search, /context, /threads: all optional ("only returned if"), no MUST. m.room.member: if prev_content is not present the previous membership must be assumed as leave; transitions: invite->leave: state_key == sender = rejected, otherwise revoked; join->leave left/kicked; ban->leave unbanned; join->invite "must never happen". Direct Messaging: the only server MUST is is_direct on the invite member event; the invitee client "may" use it; nothing about the join event / unsigned.prev_content (js-sdk behaviour). Stripped state: only sender/type/state_key/content: NO unsigned. Redacted events stay redacted when requested later: a redacted predecessor's prev_content must be the redacted content (for m.room.member only `membership` survives (+ join_authorised_via_users_server in v11)), so is_direct would disappear. History visibility: prev_content MUST be omitted when the viewer may not see the predecessor.
VERDICTS: D1 OK (/members, /initialSync unchanged allowed; fl fine). D2 OK ({} for an empty predecessor, absent = none). D3 OK as a NEBU rule (spec orders by DAG/stream): label it; CAVEAT: a same-ms invite+join tie makes the invite the successor of the join = join->invite which the spec says "must never happen": acceptable only because D4 stops new ties; legacy rows and the eu writers can still produce it: record on eu/fc. D4 OK (no CS-API rule on origin_server_ts choice; a lead of up to invite-lead+1 ms is a minor deviation). D5 OK (decline = invite->leave with sender == state_key is "rejected the invite": Element's text follows the spec table). D6, D7 OK (D7 required by spec). D8 WRONG as worded: not spec-equivalent: with history_visibility `joined` the spec DENIES a late joiner the old event, so prev_content of the current event MUST be omitted for them: it is a documented DEVIATION (es): label AC7 "pins known deviation es" or run it under `shared` (default; late joiner allowed). D9-D12 no objection.
CORRECTIONS: D8 wording (deviation, not equivalence; AC7 pins the known deviation es or uses `shared`).
MISSING TESTS: same content set twice (A, then A again): the second event still carries prev_content = A (no dedup); rooms.leave timeline with 2 events of the same slot in ONE response: the second's predecessor is the first, same batch; invite then leave by ANOTHER user (revocation): prev_sender = inviter, sender != state_key; ban then leave (unban) predecessor at DB level (AC1 case); stripped state has no `unsigned` even when the source has a predecessor (HTTP AC4 a with a re-invite after a leave); history visibility `shared` case: the late joiner gets prev_content (spec-allowed), keep the `joined` case tagged as the es deviation; AC1(b) invite+join tie asserts + documents join->invite as the transition the spec forbids; redaction is not implemented: guard test or fl(d) note that a redacted predecessor would yield the redacted content; non-state event with the same type as a state slot (state_key absent) never gets a predecessor and never counts as one.
