Mutation results - story session-lifetime-setting (epic oauth-session-and-consent), after the test-review fix pass
================================================================================

Method: the throwaway reference implementation (reference-impl.diff) was applied to the worktree, one mutant at a time was applied on top of it, the story
tests were run (`.session-ci/quick.sh "mix test <13 files> --include integration"`: the 9 new test files + admin_reauth_button_flow_config / _cross_page,
oauth_config_cache / oauth_config tests as regression guards of the shared cache) and the file was restored. KILLED = at least one test failed.
Runner: scratchpad mutants.py (throwaway, not committed). Result: 65 mutants, 65 KILLED, 0 SURVIVED / ERROR.

New in the fix pass (N01-N12): require_admin removed (N01), validation before the gate (N02), "no change" compared with the value in effect instead of the saved
one (N03), cache table gone drops the saved value (N04), admin session ceiling reads the new key (N05) / Nebu.Admin.Auth reads it (N06), legacy extension bound
ignores the setting (N07, characterisation test), a GET route reaches the action (N08), docs without the legacy / unreadable-config decisions (N09, N12),
hint without the legacy note (N10), field prefill clamped to the minimum (N11). Existing mutants M16 (no-change), M18d (hint text) and M28 were re-targeted at
the changed code.

Notes
  * M20a-M20c and N09 / N12 (migration 000056, docs) are killed by STATIC tests (the throwaway database is migrated once from the correct file and is not
    re-migrated per mutant, so the :integration RLS tests did not take part there).
  * No equivalent mutants were left standing. Cross-NODE propagation is not mutable in one VM: it is proven through the TTL-expiry test
    (session_lifetime_cache_test.exs "at now - loaded_at = TTL ...").
