# Security review (Kassandra) — fix requests, cycle 3 (Phil decided: fix F-1, F-2, F-3)
Report: docs/stories/matrix-session-refresh-fixes/security-reports/refresh-worker-and-retry-semantics-security-review-2026-10-07.md (read it for context and rationale)

- F-1 (MEDIUM): `extend_in_place/3` (matrix_session_store.ex ~390-404) + `RefreshWorker.extend/3` (~369-377) extend `expires_at` on the same row forever (no absolute cap). Fix: `SET expires_at = LEAST($2, created_at + make_interval(secs => $4))` with `$4 = Nebu.Web.SessionConfig.matrix_session_ttl_seconds()`. No migration. Note: a client `/refresh` creates a NEW row with a fresh `created_at`, so the cap bounds devices that never refresh themselves (exactly the threat). When the cap is reached the worker simply stops extending (row expires normally -> soft_logout path). Test: worker cycle does not extend beyond created_at + TTL (backdate created_at); worker cycle still extends within the cap.
- F-2 (MEDIUM, new attack surface): a stolen, still-pending old RT can take over the session: replaying it rotates the device's active row, the real user's next request then fails with 401 M_UNKNOWN_TOKEN without soft_logout, reuse detection does not fire. Desired: detect it. Kassandra proposes: in `OidcPlug.call_opaque` treat an access token that is soft-revoked but still pending (`revoked_at IS NOT NULL AND grace_until IS NULL`) as reuse -> `delete_for_user_device` + warning log (no tokens in log). TRADE-OFF you must handle: legitimate clients have in-flight requests (long-poll /sync) that still carry the OLD AT when a rotation happens; deleting the device on those would log out legit users on every refresh. Required design: a short in-flight tolerance window measured from the rotation (`revoked_at`): within ~30 s (configurable constant/seam, documented) answer `401 M_UNKNOWN_TOKEN` with `soft_logout: true` (client refreshes, harmless; keep current behavior otherwise); AFTER the window, a soft-revoked-but-still-pending AT being presented is treated as reuse (device rows deleted, warning log with user_id/device_id only, 401 without soft_logout). Use DB time consistently (`clock_timestamp()`/`NOW()` comparison on revoked_at is acceptable HERE as a heuristic, but do not reintroduce NOW()-vs-lock ambiguity in the pending/consumed state machine). Tests: takeover scenario (attacker replays pending RT0 -> rotation; victim uses old AT after the window -> device deleted; attacker's tokens dead), in-flight scenario (old AT within window -> 401 soft_logout:true, device intact, client can still refresh with its RT). Make the window testable without sleeping (backdate revoked_at).
- F-3 (LOW): reuse detection has no time limit (`resolve_refresh_token/1` ~167, `http_public.ex` ~579-588): any historical consumed RT deletes the device. Fix: only treat as reuse while the device has an ACTIVE, unexpired row and the consumed row is young (e.g. its device session `expires_at` not passed / consumed row younger than the session TTL ceiling); otherwise plain 401 without deleting. Add tests (old consumed token against a live device: no deletion once outside the bound; inside the bound: reuse behavior unchanged).

# Cycle 4 — fixes after code-review cycle 3 + Kassandra delta review (all from the same round)
Kassandra delta: CLEAN, F-1 CLOSED, F-3 CLOSED, F-2 PARTIAL (active attacker still wins). Report section "Follow-up review 2026-10-07 (delta, code-review cycle 3)" in docs/stories/matrix-session-refresh-fixes/security-reports/refresh-worker-and-retry-semantics-security-review-2026-10-07.md.

- N-1 (MEDIUM, F-2 residual) — DESIGN CHANGE, simpler than the cycle-3 window: an ACTIVE attacker who uses his new AT2 once before the victim presents AT1 makes `mark_access_token_used/1` consume the victim's pending RT too; the victim's AT1 then falls into the hard "Token has been logged out" 401 (no soft_logout, no detection) and the attacker keeps the session. FIX (Kassandra's proposal, adopted): in `OidcPlug.call_opaque` answer EVERY soft-revoked access token (pending OR already consumed) with `deny_soft_logout` (`401 M_UNKNOWN_TOKEN` + `soft_logout: true`) and NEVER delete or reuse-detect in the plug. Remove the cycle-3 in-flight window (`superseded_beyond_grace?/1`, `superseded_at_grace_seconds/0`, seam `:matrix_superseded_at_grace_seconds`, the delete branch, and the window text in docs). Reuse detection then happens only on the already-bounded `/refresh` path (F-3 limits): victim of an active attacker refreshes with his now-consumed RT1 -> reuse -> device deleted -> both logged out (visible end of the takeover); passive case: victim recovers via pending RT1. This also removes N-2 (delete without F-3 limit; legit client with lost response after 30 s). Tests (replace the cycle-3 F-2 window tests): (a) passive: replay RT0 -> whoami(AT1) = 401 soft_logout:true, device intact, refresh(RT1) = 200 and works. (b) ACTIVE attacker: replay RT0 -> whoami(AT2) = 200 -> whoami(AT1) = 401 soft_logout:true -> refresh(RT1) = 401 and `device_rows == []`. (c) in-flight old AT right after a normal rotation: 401 soft_logout:true, no deletion. Red-before-green for (b) at least.
- N-3 (LOW): `RefreshWorker.candidates/0` (refresh_worker.ex ~230-243) keeps selecting capped/expired rows forever -> an IdP redemption every cycle that changes nothing and keeps resetting the IdP idle timer. Fix: add `AND created_at + ($n::bigint * INTERVAL '1 second') > NOW()` (ttl = SessionConfig.matrix_session_ttl_seconds()) to the candidate query; also make the worker log accurate (no "session extended" when nothing was extended). Test: a row with created_at = now - ttl - 100 causes no IdP call.
- M-1 (code review cycle 3): `extend_in_place/3` uses `LEAST($2, created_at + ttl)` which can SHORTEN `expires_at`. Make the worker strictly extending: `SET expires_at = GREATEST(expires_at, LEAST($2, created_at + ttl))`. Update test F-1a accordingly (cap in the past => expires_at unchanged, not shortened, not extended). Keep F-1b (extends within cap) and add: cap-based result never below current value.

- N-5 (INFO): add one line to Dev Notes/08-concepts.md: rows whose expires_at was extended beyond created_at+TTL by earlier worker versions are capped on the next worker cycle only for strictly-extending logic (GREATEST) => no new expiry; no release note needed beyond: "deploy logs out nobody; old pre-deploy 60s-window clients are logged out once (I-A)".
