# Notes (token-hashing-matrix-sessions)
- Side finding (NOT in scope): `POST /logout` calls `invalidate_user_sessions` with `device_id: ""` which deletes ALL of the user's sessions, not only the logging-out device's. Spec: /logout invalidates the current access token, /logout/all all devices. Candidate follow-up bugfix.
- ATDD contract assumptions (story left open): `hash_token/1` public, lowercase hex SHA-256, FunctionClauseError for non-binary; session maps from the store carry :access_token_hash/:refresh_token_hash and no plaintext; store API keeps taking plaintext; replay lock statement keeps text `refresh_token_hash = $1`; plaintext SQL gone from server/lib incl. comments; only matrix_session_store.ex and refresh_worker.ex run SQL on matrix_sessions; `hash_token(` appears >= 8 times in the store.
- Design issue for dev: RefreshWorker and HttpPublic.do_refresh_with take `sess.access_token` from session maps; with hash-only maps they need hash-addressed store variants (e.g. *_by_hash).
