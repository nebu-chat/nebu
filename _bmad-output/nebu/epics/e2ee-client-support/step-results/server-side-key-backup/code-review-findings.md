## MAJOR
M1 Unbounded memory/storage: `room_key_backup_store.ex:260-271` (read_sessions(:all)), `:302-321` (shape_sessions, Jason.decode! per row), `http_room_keys.ex:111-127` (get_keys): GET /room_keys/keys loads, decodes and re-encodes every row of a version in one request process; 100 000 sessions x 8 KiB = 800 MiB per version (more decoded), 10 versions = ~8 GB per user, no aggregate byte cap (account data has 4 MiB), reads unthrottled => concurrent GETs from one account can exhaust node memory. ORCHESTRATOR DECISION: (a) aggregate stored-bytes cap per user across all live versions (256 MiB of session_data+auth_data canonical bytes, enforced under the lock like the other quotas; refusal 403 M_FORBIDDEN, nothing stored) via a config seam; (b) GET /keys* builds the response by splicing the stored JSON text into iodata (no decode/re-encode) so memory stays ~1x; (c) the bulk reads (`GET /keys`, `GET /keys/{room}`) get their own rate-limit bucket (30/min, burst 10 per user); single-session GET and version GET stay unlimited; (d) default per-version session cap stays 100 000.
