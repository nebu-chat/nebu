# Test review (pre-dev): to-device-messaging (REQ-2026-012)

Reviewer: nebu-test-reviewer (read-only, static; nothing run). Verdict: strong suite. 2 MAJOR (missing security negatives), 12 MINOR, 5 INFO. All 5 Gherkin scenarios and oracle behaviours 1-20 covered with non-vacuous tests (weakest: 12 wake-up, 14/15 loose assertions). Spec fidelity good (event exactly sender/type/content, 200 `{}`, `to_device` always emitted, txn scope device + path, `*` at send time, ordering, ack on next token, redelivery on older since; all error codes covered). GenServer `ToDeviceSendGate` crash/restart covered; queue/txns/ack DB-only with static scans.

## MAJOR
M1. Sender isolation not tested at the user-level caps (limits_http_test:274-314, 316-362): the per-sender share (100) is count-only and per DEVICE; the reference eviction is global oldest per user (reference-impl.diff ~808-811, no sender preference), so ONE co-member can evict every other sender's older messages (5 victim devices x 100 x ~64 KiB = the 32 MiB user budget in ~32 requests; >= 21 victim devices trips the 2000-message cap). Needs a test that user-level eviction takes the over-share sender's rows first, or an explicit accepted residual in Decisions/11-risks.
M2. IDOR with an identical device_id on two users untested: `TD.device!` always random ids (support:70-75) while OAuth device ids are client-chosen (`device:XYZ`), so an attacker can choose the victim's id. Mutants A05/A06 drop only the device predicate; none drops `user_id` from delivery, ack, purge or the txn scope. Add tests with two users sharing one device id for sync delivery, ack by the other user's token (sync_http:154), `DELETE /devices` and logout purge (purge_test:141), send to `{uid, dev}`, txn scope.

## MINOR
m1 Decisions diverge from story Constraints (purged on session revoke vs Decision 9 and purge_test:176; idempotent per access token vs Decision 6 / send_http:501; 429 for a full queue vs eviction; "share at least one room" vs join OR invite; rate limit "consistent with send-event" vs new 60/min burst 30): update or mark superseded; docs test only reads `## Decisions` (docs_test:60).
m2 Invite reach not listed as an open question (send_http:347-353, mutant R02): "recipient only invited" counts as shared, so any user can create a room, invite anyone without consent and get a send path; also weakens the "only room co-members can wake up to 100 polls" claim.
m3 Statement-count re-pins (member_prev_content:57 = 61; history_visibility ~873 = {52,2}/{33,0}) are exact `==` pins of the reference's incidental shape (+2 idle initial, +3 incremental; part avoidable: a `lock_timeout` set_config on an idle read-only sync and a separate `pending?` pre-check): prefer ceilings (<= new, old baseline as floor); keep the real cap in concurrency_test:334-346.
m4 Vacuous/loose assertions: sync_http:276 tautology; limits:153 `assert bob3.dev`, :390 `Enum.all?(& &1.dev)`; limits:379-391 kept subset not pinned; purge:148 `status in [200,404]`; logging:163/:183 `in [500,503]`; send_http:637 `in [M_NOT_JSON, M_BAD_JSON]`; :662 `in [200,400]` (non-deterministic); sync_http:386 `length in 14..17`, :175 `ns in [[2],[1,2]]`; send_http:641 claims "txn is recorded" but never asserts; :681-686 name claims full vs backlog vs empty queue but only the full queue is exercised.
m5 Timing/flakiness: sync_http:232 `Process.sleep(500)` vs 1.5 s pg_sleep (use `TD.slow_commit_trigger!` + `wait_sleeping(1)`); concurrency:207-231, :249-261 1.5 s window (kill test can false-green on a slow runner); `wait_sleeping` counts PgSleep backends globally (support:172-177); upper bounds `ms < 1_000` (concurrency:168, deletion:171) and `< 8_000` can flake; deletion:205 `Process.sleep(30)` best-effort.
m6 Wake-up tests do not prove a wake-up (sync_http:395-404, :452-466): bound `< 8_000` ms with 30 s timeout passes with a re-poll every few seconds; oracle wants sub-second; mutant A19 (re-check after the :pg join) survives as "equivalent", the missed-wake-up window is unpinned.
m7 Boundary slack: sync byte cap `3*cost+10` (sync_http:354), fan-out cap exactly `2*cost` with no "-1" (limits:432), user byte budget has no "-1" case (limits:297, only the device budget does :255-261): an off-by-one survives.
m8 No timing proxy for the no-oracle suite (send_http:275-308): assert equal to-device statement counts for delivered vs unknown/unshared recipient via `TD.statements`; shapes for deactivated/erased/lock-busy recipients compare status and body only (purge:111, deletion:156,177).
m9 Weak negatives around the request: no missing/non-JSON Content-Type, no chunked or lying Content-Length on the 64 KiB cap (Plug.Test always sends sized application/json); Cowboy listener not in the path; unrescued handler crash not forced (acknowledged).
m10 Static logging scan is per line (docs_test:363-368): a multi-line `Logger.error(` or `Exception.message(e)` interpolation escapes; the behavioural quoting-fault tests are the real protection.
m11 Implementation coupling beyond the contract: `content` column type in the trigger (`content LIKE`, support:160, sync_http:221), `:pg` group "user:<id>" (support:181), `__opts__`/queue `oauth_cleanup`/max_attempts 3 (purge:231), `to_device_shape?` (routes:189), eviction-log wording regex (limits:215), regexes on protected.ex/server.ex source (docs_test:296-321), ~34 docs tests regex-match prose (docs_test:88-226), migration test greps SQL (probably repo convention).
m12 `TD.statements` (support:208-213) counts only the calling process's statements with needle "device" (also matches auth/session queries); a leaner impl that moves work into another process escapes counting (false-green for concurrency:305-346); "more than pool connections" claim (concurrency:177) never asserts the pool size.
