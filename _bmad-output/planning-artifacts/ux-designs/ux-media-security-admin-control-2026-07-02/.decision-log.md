### Decisions
_(appended chronologically as distillation proceeds)_

**D1 — Realtime engine: LiveView, not Vue/SSE.** PRD §Admin UI Architecture and
ux-design-specification.md describe "SSR Go-Templates + minimal Vue + SSE". The
epic (Story 5b/7/10) mandates **Phoenix LiveView + Phoenix.PubSub** (row-level
updates, LiveView confirm-modals, `/admin/media` LiveView). Epic is the newer,
authoritative source and matches the real stack (HEEx under
`server/lib/nebu/admin/templates/`, ADR-021 Pure Elixir). → EXPERIENCE.md
specifies LiveView/PubSub interaction. The URL-addressable-state principle
(PRD FR50/NFR-O4) still holds: filters/sort/pagination live in `params`.

**D2 — Media-state color vocabulary = explicit new tokens.** Obsidian defines
only a 3-level ops traffic light (green `status-ok` / amber `status-warn` /
red `status-error`) + neutral. The epic (Story 5a) deliberately introduces
**teal** (`released`) and **coral** (`admin_blocked`) to avoid overloading the
ops light. → DESIGN.md defines dedicated `media-state.*` tokens rather than
silently collapsing them onto ok/error. Mapping honored from Story 5a:
processing (`reserved`/`quarantined`/`scanning`) = amber, `released` = teal,
`infected` = red, `admin_blocked` = coral, terminal (`deleted`/`hard_deleted`)
= gray, `scan_failed` = amber (nav badge). Every badge = color + icon + text
(never color alone — Obsidian colorblind rule). [DECISION FOR PHIL: confirm
teal/coral as new tokens vs. reuse status-ok green / a red variant.]

**D3 — status-warn-bg conflict.** Spec table `#431407` collides with
`color-primary-subtle`; prototype uses `#451a03`. → Adopt prototype value
`status-warn-bg: #451a03` so warn and primary-subtle stay distinct.

**D4 — PRD gap flagged, not invented.** PRD has NO malware-scan / quarantine /
media-policy / object-storage domain requirements (media server is a Growth
line item; NFR-C3 "Postgres-only, no external service" is even in tension with
the S3 object-storage config screen). The epic is net-new domain. UX contract
sources scan/quarantine domain rules from the EPIC; the WCAG-AA / audit /
four-eyes / role-gating / URL-state / DE+EN constraints from the PRD still bind.
[NOTE FOR UX: recommend new PRD FRs/NFRs + an ADR for the S3 vs on-premise
data-locality tension.]
