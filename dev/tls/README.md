# Local HTTPS front door (`dev/tls`)

Serves **everything on one origin, `https://nebu.localtest.me:7443`**: Element Web, the Matrix API, the OAuth
endpoints (`/oauth2/*`, `/.well-known/openid-configuration`), `/account` and the admin UI (`/admin/`). Use it to
test the OAuth 2.0 authorization server (it needs an https issuer whose host has at least two DNS labels, so
`localhost` does not work) and the admin UI together, without switching between `localhost` and a second host.

The nginx of the Element Web container terminates TLS with a local CA; the server behind it stays plain HTTP.

## One-time setup

1. **Hostname.** Many home routers block public names that resolve to loopback (DNS-rebind protection), so add
   both names to `/etc/hosts`:
   ```
   127.0.0.1 dex.localtest.me nebu.localtest.me
   ```
2. **Certificate:** `make dev-tls-certs` creates `dev/tls/certs/` (git-ignored) with a local CA and a server
   certificate for `nebu.localtest.me` and `localhost` (397 days; run it again to renew, the CA is reused).
3. **Trust the CA** in your browser, otherwise Element's service worker cannot register. macOS:
   `security add-trusted-cert -r trustRoot -k ~/Library/Keychains/login.keychain-db dev/tls/certs/ca.pem`
   (Firefox: Settings > Certificates > Import `ca.pem`).

## Run

```
make dev-tls                # postgres, dex, minio, server, element (nginx + TLS)
make dev-tls-oauth-on       # oauth_enabled=true, oauth_issuer_url=https://nebu.localtest.me:7443
make dev-tls-oauth-off
```

The two targets write the `server_config` keys directly. The same switch is in the admin UI (`/admin/`, Configuration,
section "OAuth 2.0 authorization server"): the Admin UI route needs a fresh sign-in at Dex and an acknowledgement, and writes an audit row.

Then open `https://nebu.localtest.me:7443/admin/` and complete the Bootstrap Wizard once (OIDC issuer
`http://dex.localtest.me:5556/dex`, client id `nebu-gateway`, secret `nebu-dev-secret`; dev users in
`dev/dex/config.yaml`, password `changeme`). A new OAuth client (for example Element Web) registers itself and
stays **pending** until an admin approves it under the OAuth client approvals in the admin UI.

| What | URL |
|---|---|
| Element Web | https://nebu.localtest.me:7443/ |
| Admin UI | https://nebu.localtest.me:7443/admin/ |
| Account page | https://nebu.localtest.me:7443/account |
| Dex (the IdP, plain HTTP) | http://dex.localtest.me:5556/dex |

## Things to know

- **Server name.** The admin login's redirect URI is a fixed value built from `NEBU_SERVER_NAME` and
  `NEBU_ADMIN_SESSION_SECURE` (never from the Host header). The override sets them to
  `nebu.localtest.me:7443` and `true`, so on this stack Matrix user IDs look like
  `@alice:nebu.localtest.me:7443`. Do not reuse a database that was created with `NEBU_SERVER_NAME=localhost`
  (`docker compose down -v` first).
- **Dex** (`dev/dex/config.yaml`) lists the matching redirect URIs for `https://nebu.localtest.me:7443`.
- **HTTP/2.** The server sends an empty `upgrade:` response header on `/admin`, which is invalid in HTTP/2;
  `nginx.conf` drops it (`proxy_hide_header Upgrade`). Any other HTTP/2 front end needs the same.
- Changing the code does not rebuild the server image: use `make redeploy` (it only recreates `server`).

## The same stack in CI (`e2e-oauth-https`)

The GitLab job `e2e-oauth-https` (`make test-e2e-oauth-ci`, `scripts/e2e-ci.sh oauth`) starts exactly this stack (`docker-compose.yml` + `dev/tls/docker-compose.tls.yml`) in a DinD daemon,
with a CA generated by `dev/tls/gen-certs.sh` in the job, `oauth_enabled=true` and the issuer `https://nebu.localtest.me:7443`, and runs the OAuth 2.0 Playwright scenarios against it
(`features/oauth/**`, `oauth-client-approvals`, `oauth-client-revocation`, `oauth-switch`). Playwright runs in a container on the host network with `--add-host nebu.localtest.me:127.0.0.1` and
`dex.localtest.me:127.0.0.1` (no `/etc/hosts` edit), ignores certificate errors and answers the fake client redirect targets with local stub servers (`e2e/fixtures/client-stubs.ts`).
Locally the same run is `make test-e2e-oauth-ci` (it uses ports 7443, 5432, 5556, 8008 of the host: stop `make dev-tls` first). See `docs/architecture/07-deployment.md`, section "CI Pipeline".
