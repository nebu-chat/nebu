| Anonymity by identical BODY but distinguishable STATUS is not anonymity | media-security-admin-control (1c-download-gate, 2026-07-13) | An "indistinguishable from never-existed" property was claimed for `admin_blocked`, implemented as `451 + M_NOT_FOUND` with a body byte-identical to the genuine `404 + M_NOT_FOUND`. The status line (451 vs 404) is itself the oracle: `(451, M_NOT_FOUND)` UNIQUELY fingerprints admin_blocked, distinguishing it from never-existed/deleted/infected (all 404) AND from pending (451 `M_NOT_YET_UPLOADED`). Worse, it leaks the exact thing ADR-026's own PROSE said it prevents — human-admin block (451) vs automated-scan `infected` (404). ROOT CAUSE: self-contradictory spec — ADR-026's table said 451, its prose argued for 404; the dev faithfully coded the table + AC2. RULE: when a "these two responses must be indistinguishable" requirement appears, audit EVERY observable channel end-to-end — status line, all response headers (`Cache-Control`/`ETag`/`Vary`), body bytes, and timing — not just the JSON body the test happens to assert. A test that asserts `status == 451` while commenting "indistinguishable from a 404" is proving the opposite. True indistinguishability = identical status AND identical body. Dormant until the mutation path (Story 6a admin-block trigger) ships → then live (cf. "// MVP → live when wired"). **CLOSED 2026-07-19 by Story 6a**: caught live during 6a's own security review — verified `download_gate(:admin_blocked)` still returned `451` (the finding was correctly dormant-then-live, exactly as predicted, and had NOT been fixed by any intervening story). ADR-026 corrected (table + prose), `media_download_gate_test.exs`/`media_download_stall_test.exs`/`media_admin_actions_test.exs` assertions updated to require identical status, not just identical body. Rule stands as written for future review of any other "these responses must be indistinguishable" requirement. |

FIX at supersession time: drop the legacy column + all refs, OR add a CHECK/trigger binding `deleted=true ⟹ state IN ('deleted','hard_deleted')`. Companion to the Epic-14 "non-atomic dual-column state" family. |
