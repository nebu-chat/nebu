plus its acceptance/invariant tests and the grep-invariant support module.

**Finding summary:** 0 CRITICAL, 0 HIGH, 0 MEDIUM, 2 LOW, 1 INFO → **CLEAN / APPROVED**.
Report: `docs/stories/media-security-admin-control/security-reports/1b-state-machine-module-security-review-2026-07-13.md`.

**What held up (verified, not assumed):**
- All 3 SQL attrs (`@sql_lock_state`, `@sql_update_state`, `@sql_insert_transition`) fully parameterized; zero interpolation.
- Atomicity: UPDATE then INSERT in one `Repo.transaction/1`; `query!` raise → whole txn rolls back. Fault-injection test (`%{"bad"=><<0>>}` metadata) proves the UPDATE rolls back with the failed INSERT. No state-without-ledger-row, no ledger-row-without-state.
- TOCTOU closed by `SELECT … FOR UPDATE` — concurrent transitions on same media_id serialize; T2 re-reads new from_state.
- Actor guards enforced IN CODE both directions: `{:system, non_nil}` and `{:admin, nil}` rejected pre-DB with `{:error, :invalid_actor}`.
- UUID via `Ecto.UUID.dump!/1` → 16-byte binary bound as param; malformed → raises → rollback (fail closed). No injection/type-confusion.
- `String.to_existing_atom/1` (not `to_atom`) on DB-read state → no atom-exhaustion DoS.
- Grep-invariant exclusion is EXACT relative-path equality (`nebu/media/state_machine.ex`), not basename — same-named file elsewhere is NOT exempted. Regex `WHERE`-negative-lookahead prevents the false positive on `SET compressed=true WHERE state=…`.

**LOW/advisory notes (non-blocking, both fail closed):**
- L-1: `actor_type` not code-whitelisted — a 3rd actor_type (`{:root, uuid}`) relies on the 1a `media_transition_actor_type` ENUM to reject it (raises → rollback). Consider an explicit whitelist clause returning clean `{:error, :invalid_actor}`.
- L-2: `transition/4` return contract not exhaustive — DB-layer faults (bad UUID, NUL metadata, unknown from_state atom, non-binary actor_id) propagate as RAISED exceptions out of `Repo.transaction/1`, not `{:error,_}`. Atomicity intact; downstream callers must expect raises.
- I-1: metadata stored verbatim in JSONB (safe here, parameterized) → Story 6 admin-UI rendering is a stored-XSS surface. Ties to existing media-epic watch-list.

**New patterns discovered:** none new — reinforces existing "DB-enforced immutability is the authoritative layer, app-level checks are DiD" theme (ADR-031). Grep-invariant-as-DiD is a clean example of a tripwire that correctly does NOT overclaim.

**Accepted risks this session:** none newly accepted.

**Follow-up:** carry I-1 into the Story 6 (admin media UI) review — metadata + filename + content-type rendering in the admin origin is the flagged stored-XSS surface. Re-confirm L-1/L-2 were left as-is or hardened when 4a extends the guard table.
