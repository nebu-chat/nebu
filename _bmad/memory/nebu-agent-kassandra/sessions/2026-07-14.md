## Story 2a-post-media-create (media-security-admin-control) — security review

**Verdict: APPROVED.** 0 CRITICAL / 0 HIGH / 0 MEDIUM / 2 LOW / 3 INFO.
Report: `docs/stories/media-security-admin-control/security-reports/2a-post-media-create-security-review-2026-07-14.md`

`POST /_matrix/media/v1/create` — reservation half of async upload. Reads no body, trusts no
client input, auth-gated (OidcPlug), reserves one `media_files` row (`:reserved`) atomically
with its genesis `media_state_transitions` audit row via the new `StateMachine.create/1`.

### Verified-clean (all pipeline-flagged design decisions held up)
- Actor contract NOT widened: `{:system, nil}` pre-existed in 1b's `@type actor`; `@transitions`
  + `transition/4` untouched. Genesis is additive INSERT-from-NULL, hardcoded `'reserved'`/`'system'`.
- Empty crypto placeholders (`aes_key_hex=''`, `nonce_hex=''`) UNREACHABLE by decrypt today —
  `download_gate` serves only `:released`; `:reserved` → 451 before `fetch_and_decrypt`.
- `Nebu.Matrix.active?/1` read-only, called only with caller's own MXID (no arbitrary-user probe).
- Accountability intact: uploader in `media_files.uploader_user_id`; NO reader consults
  `media_state_transitions.actor_id` (grep-confirmed) → NULL actor_id misleads nothing.
- media_id: 128-bit strong_rand_bytes, PK-unique, ONE bounded retry.
- Pending-count query backed by `media_files_uploader_idx` → no scan-DoS.

### Findings (all advisory)
- F-1 LOW: `count_pending_reservations/1` fails OPEN on DB error — acceptable, self-limiting
  (same Repo insert fails too), soft business limit not a security control.
- F-2 LOW: no per-IP RateLimit on `create` (siblings upload/preview_url have one) — DoD parity.
- F-3 INFO **watch-flag**: no reaper for expired `:reserved` rows this story; stale reservations
  count against the 20/user cap forever → self-lockout + retention. Carry to cleanup/expiry story.
- F-4 INFO: `active?/1` public arbitrary-user signature — flag any future caller passing a
  client-supplied MXID (would extend the M_USER_DEACTIVATED accepted-risk oracle to is_active).
- F-5 INFO: `is_binary` guard → nil identity would 500 not 401; non-reachable (OidcPlug guarantees).

### Pattern note
Same shape as 1c: async-upload placeholders/states are safe ONLY because `download_gate` is a
strict `:released`-allow-list. Every future state/column added to `media_files` before it has a
real value relies on that gate staying allow-list. Keep watching the gate as the epic adds states.

## Story 2b-put-media-upload (media-security-admin-control) — security review

**Verdict: CLEAN.** 0 CRITICAL / 0 HIGH / 0 MEDIUM / 1 LOW / 3 INFO.
Report: `docs/stories/media-security-admin-control/security-reports/2b-put-media-upload-security-review-2026-07-14.md`

`PUT /_matrix/media/v3/upload/{serverName}/{mediaId}` — async-upload companion. Validates
reservation (ownership/expiry/state) → hash → gzip → AES-256-GCM → S3-key template → S3 write →
persist row → `:reserved`→`:quarantined` → scan-enqueue (no-op stub, Oban not wired). First caller
of `mime_denylist_rejected?/1` (9c), `compute_key/2` (11c), `Storage.compress/1` (12).

### Key traces (reusable for Story 2c — same `store_and_quarantine/7` seam)
- **compute_key inputs safe.** media_id/server_name reaching `compute_key` are the exact values
  that byte-matched a reservation via `lookup_reservation` `WHERE server_name=$1 AND media_id=$2`
  equality. 2a stores media_id = 128-bit strong_rand base64url (no `/`, no `..`) + server_name =
  config constant; uploaded_at = server clock. `{media_id}` is a MANDATORY template placeholder →
  every key collision-unique even under an admin custom template. No traversal/overwrite.
- **Auth:** whole media router behind OidcPlug (router/media.ex:51); PUT authenticated. Ownership
  check = defense-in-depth. Ownership checked BEFORE expiry/state → non-owner always 403, no state
  oracle to non-owners.
- **filename NOT reflected.** `row.filename` has ZERO readers (grep). Download Content-Disposition
  uses the URL path segment, not the stored column. Coordinator's header-injection question = "no,
  not today". Watch-flag F-2 for the download-wiring story (sink media.ex:637/718/720 interpolates
  `filename="#{...}"` unescaped → quote-breakout when row.filename is wired in).
- **No content-type case bypass:** base_type/1 (media.ex:733) downcases + strips params before both
  @blocked_upload_types (exact `in`) and mime_denylist prefix check.
- **TOCTOU (accepted MINOR-1):** self-vs-self only (both PUTs pass uploader_user_id==user). Worst
  case = owner corrupts own upload (key/cipher mismatch → GCM auth fail on own download). No
  cross-user/unauth. 2c deferral sound. LOW.
- **Migration GRANT correct:** media_files in 000001, same migration as blanket grant (000001:288 +
  :672); ALTER inherits it. NOT the #86 later-table fail-open. Flagged comment's #86-shaped
  wording as doc hygiene (F-4). media_files no RLS = pre-existing standing gap (F-3).

### Prior-round findings verified genuinely fixed
1. MAJOR-1 (persist/transition failures swallowed → false 200): fixed via `with … else -> 500`
   (media.ex:438-457). Confirmed.
2. MAJOR-2 (@blocked_upload_types missing on async path): added media.ex:365, checked FIRST before
   admin mime_denylist; base_type normalization means no case bypass. Confirmed.
3. MINOR-1 TOCTOU: accepted/deferred — independently judged sound (self-vs-self). Also confirmed

## Story 2c-sync-upload-shared-pipeline (media-security-admin-control) — security review

**Verdict: CLEAN.** 0 CRITICAL / 0 HIGH / 0 MEDIUM / 0 LOW / 4 INFO.
Report: `docs/stories/media-security-admin-control/security-reports/2c-sync-upload-shared-pipeline-security-review-2026-07-14.md`

Refactor: sync `upload/1` → `store_upload/4` → new `create_and_store/6` now calls the SAME shared
`encrypt_compress_and_store/5` as 2b's async PUT, and creates its row directly in `:quarantined`
via new `StateMachine.create_quarantined/1`. Replaces old inline `Crypto.encrypt/3` +
`storage_module().put/2` + `DB.insert/1`.

### Key verdicts
- **2b F-1 TOCTOU deferral RESOLVED (not just deferred).** Sync mints a fresh 128-bit media_id and
  INSERTs a new PK per request → no shared pre-existing row to race (async raced the /create
  reservation row). Shared fn holds no mutable state; distinct media_id ⇒ distinct storage_key;
  a sync id colliding with an async reservation is caught by the PK unique_violation → one retry,
  never a cross-write. No new cross-caller race. **Structurally ruled out.**
- **create_quarantined/1** = exact mirror of create/1: parameterized SQL, hardcoded system/NULL
  actor (takes NO actor arg → no injection channel for admin actor_id), atomic UPDATE+INSERT fails
  closed, clean :media_id_taken. Upholds all 1b invariants.
- **Fresh key+nonce per call, SHA-256 on RAW body before compress, one-retry cap, compute_key gets
  only server values, filename=nil into nullable col** — all verified in code.
- Confirmed by DIFF: upload/1, over_content_length?, read_full_body, @blocked_upload_types, size
  const, router/media.ex (OidcPlug+rate-limit) ALL UNTOUCHED.

### SECURITY IMPROVEMENT found (worth remembering)
Old sync path used `DB.insert/1` (@sql_insert, 9-col, does NOT set state) → row took column
DEFAULT state='released' → immediately SERVABLE, UNSCANNED. New path quarantines. The refactor
CLOSED an unscanned-content-servable window on the sync endpoint.

### Findings (all INFO)
- F-2: orphaned :quarantined row on post-create failure — not servable (1c gate), not
  attacker-forceable, deferred to reaper/ADR-030.
- F-3 **watch-flag**: DB.insert/1 residual dead write path — parameterized, no lib/ caller now,
  but a re-wire re-introduces state='released' + NO audit row; the 1b grep-invariant checker
  matches only `UPDATE...SET state=`, NEVER a state-omitting INSERT. Delete with its backfill test,
  or add CI grep gate for `DB.insert(` under server/lib/.
- F-4: create_quarantined/1 raises (not {:error,_}) on transition-insert DB fault — fails closed,
  same as create/1 L-2.

### Candidate MEMORY pattern (epic-end curation)
"Refactor that REPLACES a bespoke INSERT with the shared genesis path can silently CLOSE a
permissive-DEFAULT-column gap." When a new state ENUM has a permissive DEFAULT ('released'), every
INSERT that omits the column is a latent servable-without-scan/audit path. Audit each such INSERT;
note the 1b grep-invariant checker only matches UPDATE...SET state=, never a state-omitting INSERT.
Companion to the existing "Vestigial legacy … dead write path" pattern (#21).
