**Scope:** Staged diff for Story 6a — the first admin-facing write actions on `/admin/media`

**Finding summary:** 1 CRITICAL found and fixed before commit, 0 remaining CRITICAL/HIGH, 0 MEDIUM,
0 LOW → **APPROVED** (post-fix).

**CRITICAL (self-caught via sanctum, fixed same session):** `download_gate(:admin_blocked)` still
returned `{451, "M_NOT_FOUND"}` — a status line distinguishable from every other terminal-negative
state's `404`. This is exactly the dormant 1c finding ("Anonymity by identical BODY but
distinguishable STATUS is not anonymity") predicted would go live "once the mutation path (Story
6a admin-block trigger) ships" — and it had. The dev-agent's own first-pass fix in this same
session (before Kassandra activation) rewrote ADR-026's prose to justify the 451-vs-404 split as
acceptable anonymity — repeating the EXACT flawed reasoning the sanctum note already refuted.
Caught by reading MEMORY.md's Recurring Patterns before reviewing the diff (not by re-deriving it
from scratch) — this is what the sanctum is for. Fixed: `download_gate/1` now returns byte-identical
`{404, "M_NOT_FOUND"}` for `:admin_blocked`, matching `:infected`/`:deleted`/`:hard_deleted`/genuine
unknown-`media_id` exactly. ADR-026 re-corrected (table + prose, with accurate reasoning this
time). Updated tests: `media_download_gate_test.exs` (2 tests), `media_download_stall_test.exs`
(`@deny_table` + 1 dedicated test), `media_admin_actions_test.exs` (the new AC1 end-to-end
anonymity test). Verified 2d's `DownloadStall`/`maybe_await_stall/3` is unaffected — it gates on
`state in [:quarantined, :scanning]` only, entirely independent of `:admin_blocked`'s status-code
mapping.

**What held up (verified, not assumed):**
- Authorization: all 4 new actions route through the pre-existing `on_mount({Nebu.Admin.Auth,
  :require_admin}, ...)` gate (Story 5a's own, unchanged) — no new/separate auth mechanism, no
  privilege-escalation path. Confirmed the existing "non-admin redirected" test generically proves
  every `handle_event` clause (5a's and 6a's alike) is unreachable pre-mount.
- `AuditWriter.@known_actions` allowlist updated in the SAME commit as the 4 `Nebu.Media` functions
  that reference the new action strings (`media_blocked`/`media_unblocked`/`media_deleted`/
  `media_rescanned`) — the known repo gotcha (silent `{:error, :audit_unknown_action}` degrade) does
  not reproduce; verified via a standalone allowlist-regression test (AC7, mirrors the
  `member_added`/`member_removed`/4c precedent).
- `admin_id` type-mismatch fix (migration 000029, UUID→TEXT on `media_state_transitions.actor_id`):
  verified zero-risk via live-DB query BEFORE writing the migration (all 42 existing rows had
  `actor_id = NULL`; 0 admin-actor rows existed since this story is the first real caller) — not a
  lossy backfill. No injection risk introduced: the column is still written via a fully
  parameterized `Ecto.Adapters.SQL.query!/3` bind parameter (never string-interpolated), same as
  every other write in `state_machine.ex`; switching from `Ecto.UUID.dump!/1`-then-16-byte-binary
  to a plain TEXT bind changes the WIRE TYPE, not the parameterization discipline.
- Idempotency (AC9): Block-already-blocked / Unblock-already-released short-circuit BEFORE calling
  `StateMachine.transition/4` at all — verified via real-DB tests that this writes NO new
  `media_state_transitions` row and NO new `audit_log` entry (not just that it returns the right
  atom).
- Guard-table rejections (AC8) never write an audit entry — verified an invalid-transition attempt
  produces zero rows in both `media_state_transitions` and `audit_log`.
- Reason field / DOM ids: `reason` (admin-supplied free text) is written to
  `media_state_transitions.metadata`/`audit_log.metadata` via parameterized JSONB binds — no SQL
  injection surface (ADR-018 inline-SQL convention, unchanged). 6a does NOT render `reason` (or any
  other metadata) back anywhere in its own scope — that's Story 6b's (detail view) surface, out of
  scope here, and the existing 1b INFO note ("metadata stored verbatim in JSONB... Story 6 admin-UI
  rendering is a stored-XSS surface") is unchanged/still open for 6b, not newly exercised by 6a.
  DOM ids built from `row.media_id`/`@confirm_delete_media_id` (server-generated random 16-byte
  base64 ids, never user free text) via ordinary HEEx `{...}` interpolation — auto-escaped,
  no `raw/1` anywhere in the new template code.
- Delete confirm modal: no `window.confirm`, no `position: fixed` (epic's explicit constraint,
  `absolute inset-0` instead); CSP `script-src 'self'` compatible (the new hook lives in
  `priv/static/assets/app.js`, same-origin, no inline `on*=` handlers — consistent with pattern
  #76's rule against dead inline confirmations under this CSP).
- Rescan reuses the EXISTING `:media_scan_enqueue_module` seam (`Nebu.Media.ScanEnqueue`, already a
  real `Oban.insert/1` since 4b) rather than a second parallel enqueue call site — no new Oban
  attack surface, `media_id` fully server-derived (never client-supplied at this call site).

**Finding summary:** 0 CRITICAL, 0 HIGH, 0 MEDIUM, 0 LOW, 2 INFO → **APPROVED**.

**Independently re-verified 3 self-reported fixes, all real:**
1. **`check_infected/1` guard (dev-story/ATDD-caught)** — `admin_override_infected/3` initially
   relied solely on the shared `StateMachine` guard table to reject non-`:infected` states, but
   `:scanning`/`:admin_blocked`/`:scan_failed` -> `:released` are all independently legal edges for
   OTHER callers (clean-scan, 6a's unblock, 4a's manual clear) — an override attempt against a

   BEFORE `transition/4` in the `with` chain, confirmed via the full table-driven test (7

2. **Confirm-disabled-until-non-empty wiring** (self-caught by the pipeline agent's own code-review

3. **Focus-trap leak** (introduced by fix #2, caught in the SAME review pass) — a `:disabled`
   button is excluded from native Tab order, so the JS trap's `focusable` NodeList tracking it as
   "last" meant the wrap-around branch could never fire while the reason field was empty (the
   modal's own default just-opened state) — Tab would escape the modal entirely. Fixed via
   `:not(:disabled)` on each selector clause. This reviewer independently re-derived the mechanism
   from the code (didn't just trust "it's fixed") — traced through why a disabled element can never
   equal `document.activeElement`, confirming the leak was real before confirming the fix closed it.
