## New Patterns Added to MEMORY

1. **New IaC data-bearing resources missing `prevent_destroy`** — Companion to Epic 13 "deletion_protection = false" pattern, extended to Tofu Object Storage buckets. Rule: every customer-data-bearing Tofu resource MUST default to `prevent_destroy = true`.

2. **S3-compatible endpoint validation missing scheme assertion** — Tofu preconditions for S3-compat endpoints must assert no `http://` / `https://` prefix AND `USE_SSL=true` must be a template constant, not an overridable var, in production cloud-init blocks. Defends against operator footgun where misconfigured endpoint scheme leads to credential-downgrade workarounds.

The diff is small but the deployment-topology implications are non-trivial. The pre-existing XFF coalescing across nginx → media is the kind of thing that ONLY becomes visible when you trace the request chain end-to-end — exactly the "per-story CLEAN reviews can stack into combined HIGH at epic-end" pattern from Epic 12. The `prevent_destroy` issue almost slipped past as INFO-4 in code-review-findings. Code review evaluated it as "operational"; I promoted it to MEDIUM because data-loss-on-tf-destroy IS a security concern (availability of customer data, audit-trail destruction). Code review and security review have different severity calibrations — both views are useful, neither replaces the other.
