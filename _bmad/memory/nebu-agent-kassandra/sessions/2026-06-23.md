## SEC Gate 1 — oidc-refresh-mode-config (fix-short-oidc-sessions story 3) — CLEAN

Configurable OIDC refresh mode (offline|online) for Matrix + admin, bootstrap + runtime
(/admin/config), stored in server_config. REVIEW only.

**Verdict: CLEAN — no CRITICAL/HIGH/MED/LOW. Nothing blocks.**

Why clean (the key insight): the mode value NEVER enters the scope string as data. It only
*selects between two hardcoded literal lists* — `["openid","offline_access"]` vs `["openid"]`
(auth.ex:770) and `@base_scopes ++ ["offline_access"]` vs `@base_scopes` (sso_login.ex:326).
So even a SQL-injected/junk server_config value is INERT — no extra-scope/space/newline
injection possible. Plus full defense-in-depth: BOTH read sides validate to the enum
(matrix_refresh_mode collapses non-"online"→offline; admin_refresh_mode collapses
non-"offline"→online) AND all three write paths (ConfigLive save_refresh_mode comprehension,
BootstrapLive save_claim_mapping guard, do_complete_bootstrap `v in [...]`).

- Writer gating: ConfigLive + BootstrapLive inside live_session :admin on_mount :require_admin
  (router.ex:73). Gate runs on socket connect too (pattern #61) → save_refresh_mode unreachable
  unauth. Bootstrap promotion only in do_complete_bootstrap; post-bootstrap wizard re-gated
  (auth.ex:915). Pre-bootstrap unauth reach is by-design (no admin session to protect yet).
- No verification weakening: diff touches NO verify_token/alg/iss/aud/jwks. `openid` always
  present both modes both clients; `online` drops only offline_access, keeps profile/email →
  admin-group claim mapping intact.
- Admin default online is MORE conservative than prior forced-offline (session-bound RT vs
  long-lived logout-surviving RT). Not a downgrade.
- Dex foot-gun surfaced verbatim in both hints. No XSS (enum→boolean selected attr, HEEx escapes).

Reusable pattern (worth curating): **enum-as-selector, not enum-as-value.** When a config
value controls a security-sensitive output string (OIDC scope), the safe shape is to branch on
the validated enum and emit hardcoded literals — never interpolate the stored value into the
output. This makes the read side inherently injection-proof regardless of what a future writer
or direct-DB actor puts in the row. Contrast with the recurring "admin-saved string flows into
X" findings (SSRF URLs #40/#46, scope here). Here the team got it right by construction.
