## What I verified empirically (not from dev summaries)
- `nil` no-op (AC3): airtight at 3 layers of `Nebu.Media.Config` — `@defaults` nil, read
  `coerce_value/2`, write `validate_value/2` + `""`↔nil sentinel. `:disabled` arm issues
  zero queries. Deliberate no-`rescue` around `Config.get/0` = fail-loud/dead-letter, which
  I concur is safer than guessing a window.
- AC1: `is_integer and >0` gate; `0`/neg/float → `:invalid`. Float `1.5` passes through
  `Config.coerce_value` (only string clause is `String.to_integer`) → caught by worker gate.
- **No early-deletion off-by-one:** deletion needs SQL `<` age>N days AND Elixir floor gate
  `released_for_days > days` (→ ≥ N+1 whole days). Strictly LATER than naive boundary. Safe.
  `inserted_at` is `TIMESTAMPTZ NOT NULL` (000022) → `%DateTime{}`, UTC-consistent.
- **Soft-delete only:** `StateMachine.write_transition/6` uses state-only SQL for `:deleted`;
  the storage_key/hard_deleted_at SQL is `:hard_deleted`-only, unreachable here.
- **AC4:** `transition/4` returns `{:ok,:deleted}` only post-commit; worker matches exactly
  that → audit. No CaseClauseError-on-success path (contrast 8c's `commit_archived/1` bug).
  Allowlist entry present (the recurring 4c/6a/8a/8c gotcha — handled).

## LOW advisories logged (not fixed — pipeline-protected src, unreachable/accepted)
1. `released_for_days/1` evaluated outside per-row `rescue` (worker.ex:153). Would abort
   whole batch on a malformed `released_at` — but unreachable (TIMESTAMPTZ NOT NULL + WHERE
   filters NULL). No live poison-pill.
2. Discarded `AuditWriter.log/6` return on `{:ok,:deleted}` = state-changed-silently on
   audit failure. Pre-existing project-wide accepted pattern (Config.upsert m2, etc.).
