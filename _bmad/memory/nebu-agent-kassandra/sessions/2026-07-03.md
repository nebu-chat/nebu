# Session 2026-07-03 — security-review: server-paced-session-refresh / background-session-refresh-worker

**Mode:** per-story security-review (SEC Gate 1). Staged diff. Cycle 2 (code review passed clean).
**Verdict:** BLOCKED — 1 HIGH, 1 MEDIUM, 1 LOW.
**Report:** docs/stories/server-paced-session-refresh/security-reports/background-session-refresh-worker-security-review-2026-07-03.md

## What shipped
New `Nebu.Matrix.Session.RefreshWorker` GenServer: proactively redeems each device's upstream OIDC RT before `matrix_sessions.expires_at`, so Element Web's token-login flow (never calls `/refresh`) gets seamless server-paced renewal. Reuses `HttpPublic.revalidate_with_idp/1` + `session_expires_at/1` + `maybe_put_new_oidc_rt/2` (widened defp→def, same-domain, @doc false). Registered in `repo_children` alongside Sweeper. Two tuning env vars via `parse_ttl` (n>0 or defaults).

## The find (HIGH, BLOCKING)
The cycle-1 M1 fail-closed hard-delete (`Store.delete_for_user_device(user_id, device_id)` on confirmed IdP rejection) is scoped to the (user_id, device_id) PAIR, not the acting row. Safe for client `/refresh` (one live session, no racing sibling). NOT safe multi-node: worker is an unnamed GenServer, so every K8s node runs its own copy. Under IdP refresh-token rotation, node A redeems + rotates (T_old→T_new), node B calls IdP with the now-consumed RT → 401 → confirmed-rejection branch → deletes T_new (A's fresh row). Race loser destroys the winner's just-refreshed session → forced re-login. Fail-closed in direction (no auth breach) but attacker-independent self-inflicted DoS defeating the story's whole point. The moduledoc's cluster-safety section only reasoned about `rotate_tokens/1`'s `WHERE ...revoked_at IS NULL` guard (which IS safe) — missed that the unscoped M1 DELETE has no such guard. No test exercises the two-node interleaving (single-node suite only).

Fix offered: scope the delete to `access_token=$1 AND revoked_at IS NULL`, or make the worker a `:global` singleton.

## MEDIUM
`{:token_endpoint_unreachable,_}`/`{:discovery_failed,_}` not tagged `{:transient_check_failed,_}` (only `check_still_active` DB failures are) → transient IdP outage during a cycle mass-hard-deletes every near-expiry session. Fan-out amplifies the client path's per-request behavior. Widen the transient tag.

## Clean / verified holds

- Bounded rolling TTL: rotate INSERTs new row with `min(oidc_exp, now+ceiling)`, never derived from old expiry — no accumulation. ✓ property 2
- TOCTOU: re-select `revoked_at IS NULL` immediately before IdP call; rotation write truly atomic via guarded UPDATE. ✓ property 3 (but the DELETE is the exception — see HIGH)
- TLS peer verify enforced on IdP token endpoint (`oidc_token_exchange.ex` verify:verify_peer) — the recurring :httpc empty-ssl gap did NOT recur. Good.
- Logging hygiene clean: only user_id/device_id/reason-atom; no raw/decrypted tokens or claims. ✓ property 9
- ADR-020: three newly-`def` funcs @doc false, only called from within Nebu.Matrix (grep-confirmed). ✓ property 8
- M1 cross-session-harm: NOT attacker-exploitable — sess is DB-bound to the re-selected access_token, malicious IdP can only delete its own session; transient tag not attacker-producible. ✓ property 5 (the harm is the concurrency collateral, not attacker targeting)
