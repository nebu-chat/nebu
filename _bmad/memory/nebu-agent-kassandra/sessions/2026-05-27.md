## Findings (all LOW, advisory)
1. `matrix_sessions` table has no RLS — recurring "missing RLS on new tables" pattern; defense-in-depth gap; consistent with pre-existing `admin_sessions` precedent. No SQL-injectable surface introduced; queries parameterized.
2. `WithOpaqueSessionCheck` does not populate `ContextKeySystemRole` / `ContextKeySub` / etc. — downstream Matrix handlers see `system_role=""` for opaque-token sessions. Privilege downgrade, not escalation. Future-proofing concern if any code path ever treats empty role as privileged.
3. Opaque/JWT dispatch relies on absence of `.` in opaque tokens. Today safe (64-char hex); fragile if a future opaque format ever includes dots.

## Scope items verified clean
- SQL injection (parameterized queries throughout new DB code)
- Auth bypass: `/refresh` outside jwtMiddleware is intentional (spec MUST); gated by strictRL + bodyLimit1MiB; no other routes added
- Timing attacks: N/A — 256-bit random tokens via B-tree index lookup; no in-process secret `==` comparison
- Rate limits: `/refresh` covered by strictRL (30 req/min, burst 10) — same as /login
- Weak crypto: crypto/rand for 32-byte tokens (256-bit entropy); AES-256-GCM via SHA-256 KDF over internal_secret; standard nonce handling
- Plaintext secrets in logs: all slog calls enumerated — only err, user_id, device_id ever logged; never raw or encrypted RT/AT
- JWT validation: unchanged from prior reviews; opaque path doesn't bypass JWT validation for JWTs (dispatched correctly by `.` presence)
- Body-size limit on /refresh: 1 MiB cap
- OIDC RT AES-256-GCM: KDF + nonce + AEAD correct
- Session revocation on logout (MAJOR-A cycle-1 fix): hard DELETE via Revoke(rawToken); ownership guaranteed by middleware; 3 unit tests added
- Grace-window AC4: walked race scenarios — double-rotation always fails (revoked_at IS NULL guard); cross-user revocation not possible
- HasGraceWindow: correctly scoped (same user+device), gated by !revokedAt.Valid

## Patterns to add to MEMORY.md (next session)
1. Continued "Missing RLS on new tables" instance: `matrix_sessions` (also pre-existing `admin_sessions`). Worth a sweep to add explicit-allow RLS to all session-shaped tables.
2. NEW pattern candidate: "Multi-path authentication middleware divergence — when two middlewares (e.g. opaque + JWT) coexist as parallel auth paths, they must populate the same context keys, or downstream consumers must defensively handle missing keys. Today's `WithOpaqueSessionCheck` skips `ContextKeySystemRole` etc. — Matrix handlers receive empty role for opaque-token users (privilege downgrade, safe direction). Future-proofing: store role at session creation and surface through LookupOpaqueToken."
3. NEW pattern candidate: "Dispatch-by-token-format invariant — when dispatch logic relies on a character / shape distinction (opaque hex vs JWT dot-separated), pin the invariant with a code comment and consider strengthening the discriminator (e.g. dot-count == 2 for JWT branch instead of dot-count >= 1)."
