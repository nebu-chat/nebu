## Session — Story 10b (clamav-status-freshclam-age), UX audit gate

**What changed:** `server/lib/nebu/admin/media_health_live.ex` — new "ClamAV-Status"
`<section>` added (connected/disconnected badge, down-since timestamp, signature-age
copy + staleness badge). `server/lib/nebu/admin/clamav_status_indicator.ex` — new
poll-based helper module (`status/0`/`schedule/0`/`assign_status/2`), mirrors
`WarRoomIndicator` mechanics.

**Audit findings:**
- Color-alone signaling: PASS. Every badge state (Verbunden/Nicht erreichbar/
  Signaturen veraltet) carries distinguishing text, not just a CSS class.
- Heading/landmark structure: PASS. New `<section aria-labelledby>` + `<h2 id=...>`
  matches the throughput/duration/backlog/error-rate sections above it exactly
  (same classes, same pattern).
- **aria-live gap: BLOCKING.** The section updates on the same 2s poll tick as
  `WarRoomIndicator`, but unlike `WarRoomIndicator`'s own rendered output (topbar
  war-room pill, `layouts.ex:138`, `role="status"`) and `MediaAttentionBadge`'s nav
  badge (`layouts.ex:212`, same `role="status"` + sr-only text pattern), the new
  ClamAV section has NO `aria-live`/`role="status"` anywhere. This codebase has an
  explicit, already-written UX-gate comment (`layouts.ex:208-219`) establishing the
  rule: "a live-updating value visible... needs TWO things, not just visible text:
  (1) role=status... (2) an sr-only text equivalent." Story 10b's AC6 explicitly
  models this section on `WarRoomIndicator`'s pattern but only copied the poll
  mechanics, not the accessibility half of that same precedent. Flagged as blocking
  in the audit report back to the pipeline.
- Keyboard/focus: PASS (no interactive elements in the new markup, nothing to manage).
- DaisyUI class reuse: PASS (`badge-success`/`badge-error`/`badge-warning`, no ad hoc
  colors).
- Non-blocking nit: new badges use `<p class="badge ...">`; established convention
  elsewhere (`compliance_html.ex`, `rooms_html.ex`) is `<span class="badge ...">` for
  inline status chips. Not a WCAG violation, just a consistency deviation.

**New pattern reaffirmed for MEMORY.md:** poll-driven, appear/disappear status content
in this admin UI (WarRoomIndicator pill, MediaAttentionBadge nav badge) is expected to
carry `role="status"` (+ sr-only text where the visible content is abbreviated/iconic).
This is the established rule, not optional — future ClamAVStatusIndicator-style helpers
should follow it too.

**Follow-up:** none pending from this session; dev-story owns applying the fix.
