## Session — bugfix pipeline, sync state.events missing event_id/origin_server_ts

**What happened:** Spec-lookup request for a bugfix story: do `rooms.join.<room_id>.state.events`
entries require `event_id`/`origin_server_ts` like `timeline.events`? Confirmed via spec text
(client-server-api/index.html:15472-15553, 15672-15687): both `State.events` and `Timeline.events`
are typed `[ClientEventWithoutRoomID]` — the exact same schema. `event_id` and `origin_server_ts`
are **Required** in `ClientEventWithoutRoomID` regardless of state vs. timeline placement. `unsigned`
(UnsignedData) is optional there (not Required) for both.

**Key outcomes:**
- Confirmed story's AC1/AC2 premise is spec-accurate: dropping `event_id`/`origin_server_ts` for
  state events is a genuine MUST violation, not a style choice.
- This directly extends/resolves the known decision below — previously only `event_id` on
  `PUT /state/{eventType}` responses was tracked as a bug; now the broader `/sync` state.events
  gap (both fields, all state event types) is in active remediation via this bugfix epic.
- `GET /sync` itself: Requires auth (Yes), Rate-limited: No (per spec's basic-info table,
  line ~14978-14987) — so no 429 test obligation for sync; error-code test surface here is the
  usual auth 401s (`M_UNKNOWN_TOKEN`/`M_MISSING_TOKEN`), not sync-specific error codes. The bug's
  real test surface is structural (field presence/value-fidelity), not error-code based.

**Nebu spec decisions recorded:** None new — reaffirms existing "State events return empty
event_id (MVP)" entry in MEMORY.md Known Spec Decisions; that entry's scope should be read as
also covering `origin_server_ts` and the `/sync` response (not just `PUT /state/{eventType}`).

**Follow-up:** When this bugfix lands, update the MEMORY.md "Known Spec Decisions" entry to mark
it resolved (move out of "known bug" status) rather than leaving it as an open item.
