# Session — 2026-07-01

**What happened:** Phil asked me to flesh out the async-upload part of his draft epic
`tmp/media-epic.md` ("Media Security & Admin Control"), noting it was old. Reviewed Story 2
against the v1.18 spec (`POST /_matrix/media/v1/create`, `PUT /_matrix/media/v3/upload/
{serverName}/{mediaId}`) and rewrote it directly in the doc.

**Key outcomes:**
- The "MSC2246" framing is stale — the flow has been core stable spec since v1.7, no MSC
  reference or unstable-flag in v1.18 anymore.
- Draft had a client-supplied `expires_at` query param on `/create` — not spec-conformant, the
  endpoint takes no request params; server sets `unused_expires_at` unilaterally and must
  return it in the response (draft was missing that field).
- Draft was missing: pending-upload rate limit (429), ownership check on PUT (403), the
  `409 M_CANNOT_OVERWRITE_MEDIA` case, live expiry check (vs. cron-only), optional Content-Type
  (v1.12+), `filename` query param, and the 413 size gate independent of ClamAV's scan-size gate.
- Full corrections written into `tmp/media-epic.md` Story 2 directly (not just reported).

**Nebu spec decisions recorded:** None yet — this is still a draft epic, no ADR finalized.
Flagged in the doc that a shorter-than-24h `unused_expires_at` default would need to be an
explicit accepted deviation if chosen.
